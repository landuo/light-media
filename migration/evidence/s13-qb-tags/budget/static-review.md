## Source need and policy scope
The original qB lookup requests three seconds before each of up to nine reads, plus actual read/filter/cleanup time. The ordinary serial App call's current total 30-second runner budget truncates valid longer instances. Excluding only the trusted, exact lookup callback from cumulative worker time directly addresses that mismatch without changing default serial negotiation, other callback budgets or source delays. This is not an arbitrary longer host deadline or a claim of unbounded source equivalence.

## Actual four-file safety/correctness findings
- CallOptions carries one host-only string, not wire/worker configuration. The new mode is rejected when combined with all-host exclusion or CallerDeadlineOnly, on negotiated concurrent Call/StartCall, and for invalid/transport callback names. Zero value retains existing behavior; default Runner options and startup/Stop paths do not acquire the selector.
- The existing serial gate owns exchange. Its private wireSession selector is installed only with the invocation context and is cleared alongside host/context/budget in the existing deferred cleanup. Call counters, exact identity/epoch checks, frame/chunk limits and MaxHostCalls remain before callback dispatch. Matching a name does not supply a HostHandler or capability grant.
- Only matching callHost pauses the existing monotonic remaining-time budget; deferred resume does not replenish it. Nonmatching callbacks and worker/transport time remain charged. No separate per-callback timeout reset is introduced. Serial exchange is synchronous, so selector setup/clear does not add a parallel field owner.
- Parent cancellation and client life remain linked to the call context independently of the paused timer. Cancellation still aborts streams/cancels and joins the actual worker through the old fail path. App's admitted-serial WithoutCancel policy is not changed: this must not be advertised as new HTTP disconnect cancellation. Stop remains independently bounded; App Close seals admission/stops sessions and retained objects before waiting for producer completion.
- App selects the option only for a serial resources/v1 instance declaring the exact lookup capability, and only when an existing explicit all-host policy is absent. Concurrent CallerDeadlineOnly stays unchanged. Selection is timing, not new authority; existing callback scope/generation/configuration guards still apply.
