## Open delivery boundary, not a reason to expand this compile gate

Current ordinary serial call sites use Runner Timeout=30s without ExcludeHostTime; runnerContext therefore includes host callback time. Nine source sleeps alone request 27s, leaving roughly 3s for all requests/serialization (and possibly less with other call work). A slow-but-valid nine-read sequence can exceed that budget; source has no matching whole-call timeout. Negotiated concurrent workers use existing CallerDeadlineOnly, not this serial option. This candidate changes neither behavior. **A single real three-second App case or future fast CLI cannot prove unrestricted nine-round ordinary serial equivalence.** Keep the timing/lifetime decision explicit before calling that full operation closed; do not silently alter global timeouts or protocol. This does not block the finite native/App gates now prepared.
