# 0.58.5 后续：SQLite 读池页缓存归因

本地独占合成库，非生产数据；Go 1.26.4 darwin/arm64、与光影相同的 modernc.org/sqlite v1.60.1。每个配置在新进程内创建 4096 行 × 3000 字节的测试库，持有四个只读连接，每连接执行四次全表扫描并校验结果。禁用文件 mmap，通过驱动公开的 `DBStatusCacheUsed` 在各连接仍持有时采实际缓存字节，不把 SQLite 计数等同于 RSS。各配置运行三次取中位数。初试的进程级 `sqlite3_memory_used` 在本构建返回零，没有用于结论。

| 每连接页缓存预算 | 四个连接持有的缓存字节 | 全部扫描耗时中位 | 页缓存 miss 数 |
|---|---:|---:|---:|
| 2048 KiB | 8,638,012 | 83 ms | 65,709 |
| 1024 KiB | 4,320,828 | 78 ms | 65,709 |
| 512 KiB | 2,162,220 | 74 ms | 65,709 |

默认 2048 KiB 改为 512 KiB 在此负载下少占约 6.48 MB 页缓存；只将最大空闲连接数从 4 改为 1，并不改变四个连接同时工作时的 8.64 MB。顺序全表扫描不能预测生产点查的命中率，也没有证明 Linux 的物理驻留页会等额归还。当次仅在本地合成库比较了预算。可在仓库根目录执行以下命令复现 2048 KiB 一组，再将 `-cache-kib` 分别改为 1024 和 512。

```sh
go run ./experiments/nas-memory/sqlitebudget -cache-kib 2048 -idle 4
```

0.58.5 当时的十分钟非静置采样中，RSS 中位 155.59 MB、VmHWM 164.86 MB、容器中位 134.05 MB，GC 8.99 次/分钟。这个页缓存量级不足以单独解释距 100 MB 目标的差额，也不能将此前约 21 MB 未标记匿名页全部归入 SQLite。随后在 NAS 上对不同大小的热页集做了 ARM64 对照，记录了页缓存、点查耗时和匿名 PSS。[0.58.7 读池预算验证](nas-memory-0.58.7-verification.md)
