## 明确的行为边界

原插件顺序为写入文本、重载分类、系统通知、关闭并保存开关。R2 已按此顺序实现；真实 SQLite 拒绝通知时，已写入的新文件和分类保留，尚未关闭的开关保持开启，执行记录失败，不虚报全部成功。

原分类助手加载空根或普通解析错误时保留本进程旧的电影/电视剧映射，冷启动才从空映射开始。R2 已补齐：空白、注释、null、空映射、空列表、false、0、空字符串、普通语法错误、重复键和多文档 11 类文本均可原样写入，当前进程沿用旧分类；关闭开关并通知；冷重开后没有旧分类。非空根中明确置空/缺失的 movie 或 tv 分区会立即替换对应映射，不能一概当作保留缓存。分类与规则设置页读取同一个进程状态。普通解析失败仅记录固定脱敏警告，不把策略内容或原异常原文写入日志。

这 11 类输入和写入/通知成功及失败 2 类顺序，用完整已安装原方法在本地执行对照；ruamel.yaml 0.19.1 官方 wheel 的全部 33 个 Python 源文件 SHA 与原安装版相同。原方法只接内存文件和合成通知，不修改 NAS 或原服务；应用运行仍为 Go。参考结果与依赖摘要位于 `reload-oracle.json`、`reload-yaml-provenance.json`，可复现脚本为 `reload-oracle.py`，该脚本不是运行依赖。

仍明确拒绝路径穿越分类名、循环/超限 YAML、自定义或危险标签、非空列表等未支持的原生结构，且不构造/执行任何标签；这些拒绝不冒充原版已实现功能。普通空/语法错误策略不再被此安全边界误拦。平台对未知副作用的启动保护仍生效，不自动重放结果丢失的写操作。

真实浏览器已验证正常规则→空策略→普通语法错误的保存交互与关闭开关；真实 server/HTTP 手动整理预览在热进程保留旧分类目录，冷启动后移除该目录，未重复生成插件执行和通知。最终二进制已再次完成空策略保存、热进程手动预览、同一二进制冷重开预览及执行/通知不重放的真实浏览器验证；普通解析失败冷启动的空映射及固定警告也单独核对。早期与最终构建的报告分别保留，最终 UI 报告使用同一最终二进制 SHA。

## 最小正式迁移步骤

由最终交付者执行，当前未执行：

1. 部署包含插件平台的最终 Go 版本，先确认新实例已正常初始化插件表。只停止新实例进入独占时段，不修改或停用原 MoviePilot；原插件已经关闭，没有两套调度同时写的问题。
2. 重新只读核对原源码 SHA、仍已安装/版本 1.3、`enabled=false`、恰好两个字段、KV 为 0；在同一只读 SQLite 事务中采集配置和 KV。当前值若变化，重新审核，不套用旧摘要。
3. 核对原 `content`、原全局分类文件和目标全局分类文件 SHA 仍相同。若不同，停止；不能为了导入停用插件而覆盖目标全局策略。
4. 将原配置从读取进程直接经内存管道输入 owned `category-migrate-owned`。默认只读 dry-run，要求显式目标绝对路径、审核后的原 JSON SHA 和策略 SHA；目标实例锁必须空闲、插件 schema=1、无运行核心任务/待执行插件任务。不会创建数据库或密钥，不接受未经同一收据认领的现有 CategoryEditor 目标。
5. 核对 dry-run 后，使用相同输入显式 `--apply`。工具调用真实 `BeginMigration`/`Import`，在事务中保存安装、加密配置和迁移收据，`desired_enabled=false`，不排 `init/reload`、不创建 KV、定时器或通知、不写全局策略。相同来源重放沿用收据，不回滚后续用户编辑；若后续值不同，校验失败而不覆盖。
6. 冷启动新服务，核对卡片关闭、表单原内容摘要、安装/收据各 1、KV/该插件任务/通知均 0、目标全局分类文件 SHA 不变。以新服务实际 UI 和后台状态作为正式迁移收据。普通保存时保持开关关闭；用户以后显式开启保存才应用新策略。

工具源位于本轮副本 `work/category-migrate-owned/main.go`，仅为交付工具，不加入公共 API、用户配置流程或正式 focused 运行时代码。Linux/amd64 纯 Go 二进制可由该副本构建；本轮只做本地独占实例验证，没有向 NAS 传输或执行工具。其 `OpenStore` 会执行既有 schema 初始化，因此前置拒绝旧 schema、运行中实例及运行核心任务，不能代替停止服务步骤。

调用参数（配置只走 stdin，切勿写文件、聊天或命令行参数）：

```text
category-migrate-owned --target-data-dir /absolute/new/data \
  --expected-source-config-sha <reviewed-original-json-sha256> \
  --expected-policy-sha <reviewed-matching-policy-sha256>
```

审核完成后相同调用追加 `--apply`。stdin 对象字段为 `config`（原对象）、`config_sha256`、`content_sha256`、`kv_count:0`；普通输出只有摘要和收据元数据。
