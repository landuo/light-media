实现与安全边界

- 接受事务同时写入来源密文、站内历史、原运行接受收据、初始路由锚点与处理中标记。来源绑定真实 event 执行、实例、generation、config revision、原始输入摘要、notify 处理器及唯一 site.refreshed/* 批次。SDK只能提供已绑定批次ID，不能自造通知内容、接收者或来源证明。
- 标题、正文与“站点”分类沿用原有统计构造；完整信封仅进私有密文，站内历史保留清洗后的投影。读取和续跑要同时验证来源密文、原始运行、接受收据、路由初始摘要及历史摘要；删改任一证据均拒绝续跑。
- 处理中指纹与成功 last_notify 分离。共享 Router 无异常完成时，在同一个完成事务保存 last_notify；源路由异常不覆盖既有成功KV，之后新的真实事件可按原行为再执行。重复同一路由、崩溃或发送结果未知都不自动重发。发送器失败被原队列消费、Router 正常返回的语义不被改成源异常。
- 同实例正常通知持独立 gate，外部发送和路由不持 pluginMu 或 SQL事务。不同实例的配置、KV、历史、来源、队列与去重不混用。旧完成操作须通过原 generation、config revision、当前处理中指针和原 data revision 检查，不能覆盖重置/重装或较新编辑的数据。
- 提交回执丢失先读回相同收据，不重建第二份消息；未完成路由保持 reconcile_pending，完成后按真实来源结果恢复成功或失败。后台只续跑已接受路由，不重放 SDK、不重新采集站点。旧本地通知收据不会升级为新的外发任务。
