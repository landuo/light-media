改动及严格行为
通过直接调用 Frame.MarshalJSON，去掉 json.Marshal(Frame) 对自定义 Marshaler 结果的重复标准库扫描；小帧复用已经编码的字节，避免再次序列化。内部仍通过 encoding/json 编码 rpcMessage/rpcValue，RawMessage 验证、压缩、HTML 及 U+2028/U+2029 转义没有改为自制 JSON 实现。
成功读取物理帧和重组消息时直接调用 Frame.UnmarshalJSON，内部 strictJSON 对字段、尾部和类型的检查保持，不全局替换通用 strictJSON。直接解码失败时回退原 strictJSON(raw, frame)：旧外层 Decoder 可能先写入接收对象，再因尾随对象/null/垃圾拒绝；回退保留成功与失败后的完整 receiver 状态，而非只比较是否报错。非法输入可能多解析一次，本轮不宣称改善恶意或错误输入吞吐。
直接 MarshalJSON 的错误不再被外层 json.MarshalerError 包裹，但这些传输调用点原本就映射为固定本地错误码；原 invalid_frame/frame_limit 等对外分类不变。保留取消/abort 与编码的原顺序、字节计数、newline、短写/I/O 错误、物理/逻辑/会话限额、ACK、身份及序列验证。不改 16MiB 载荷、64MiB wire 限额或原 90 秒 Runner 预算，也不延长 TorrentTransfer 表单的 10 秒预算。

回归证据设计
transport_codec_legacy_test.go 保存基线 writePhysical/readPhysical/write/read/acceptChunk 独立旧实现，不随优化同步改写。等价测试覆盖四类 frame、小帧/分块、编码精确字节、成功/失败及零值/非零 receiver、未知字段、尾随值、null、非法 RawMessage/UTF-8、取消/abort、边界相等与超限、短写、ACK 身份/顺序及组装状态和全部计数。跨独立调用只归一化随机 request/transfer ID，实际物理帧另逐字节对照旧编码；相同具体输入流的 ACK 精确比较。
错误比较独立核对 nilness，并对用例定义预期本地错误，防止未知错误被 codeOf 空串误判成功。共享 oracle 的 jsonrpc.go、protocol_test.go 和 large_transport_test.go 以 SHA 锁定，避免两侧随共同依赖一起漂移；原最大载荷测试及断言未改。FuzzTransportCodecDecodeEquivalence 仅执行普通 go test 的种子，未开展 fuzz campaign，不宣称完成随机模糊测试。

历史及结论边界
