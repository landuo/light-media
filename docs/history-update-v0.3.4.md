# v0.3.4：重复整理更新原历史

依据用户 2026-10-15 的反馈，同一资源重复整理时更新原整理记录，不再随着执行次数增加列表行数。本记录仅说明本次历史行为修正。

## 当前规则

- 同一源文件保留稳定的历史记录 ID，内容反映最新一次实际提交的整理：影视信息、源和目标路径、状态与失败原因。失败后成功、成功后失败都更新同一条。
- 历史重新整理、源文件缺失时使用原目标继续整理、文件管理中多次整理受管目标，均沿用原资源的历史归属。
- 不同源文件各自保留记录；同一 TMDB 的不同剧集、不同资源不按影视编号合并。现有同源重复记录也在列表中统一展示。
- 先选择最新执行，再搜索、筛选状态和分页，避免旧标题、旧路径或旧成功状态再次显示。仅预览不改变整理历史。
- 删除历史隐藏该资源截至确认时的执行；旧重复记录不会因此重新出现，后续真实整理仍可更新并显示。删除窗口确认后若历史已更新，则要求刷新后重新确认。

## 执行与恢复边界

界面的稳定历史 ID 与实际执行文件 ID 分开。原有整理计划、任务、文件快照和恢复收据继续保留；重新整理、删除文件和重试按对应的真实执行核验，整理队列取消也只作用于选中的执行，不会因历史更新而取消其他任务。

执行排序及隐藏截止点使用归一化后的任务创建时间与任务 ID，不依赖 SQLite 隐式 rowid。RFC3339Nano 小数补齐到固定精度，避免 `.1Z` 与 `.11Z` 的字符串排序颠倒；备份恢复后也不因 rowid 变化而永久隐藏后续任务。

## 本地验证

以下均使用隔离数据库、独占临时目录和合成小文件，未对 NAS 真实影片执行整理或删除。

| 范围 | 结果 |
| --- | --- |
| 连续失败后成功、成功后再次失败 | 同一稳定 ID，仅显示最新结果；各次原始执行仍可读取 |
| 修改影视身份与目标、旧计划迟完成 | 旧标题、旧路径及旧成功状态不泄漏到当前搜索与筛选 |
| 仅预览、不同剧集使用相同 TMDB | 预览不更新历史，两集实际导入后仍为独立记录 |
| 隐藏历史后再次整理 | 旧记录不复活，新提交可继续显示同一资源 |
| 源缺失回退原目标、连续两次文件管理重整 | 实际导入和清理通过，历史来源保持不变 |
| 旧队列执行取消、旧格式同源计划 | 取消精确作用于旧执行；既有重复自动归并且不改写原计划 |
| 真实 `Store.Backup` 与 `New` 恢复 | 隐藏状态保留，恢复后新提交可显示；同时验证 `.1Z`、`.11Z` 的先后顺序 |

新增回归位于 `internal/app/history_upsert_test.go`、`internal/app/history_upsert_backup_test.go`，以及独立的删除保护回归 `internal/app/history_upsert_delete_test.go`。历史更新的定向回归和竞态检查已通过，备份恢复与时间精度用例也已定向通过。

本机 SQLite 的 `VACUUM INTO` 实际保留了带索引的任务表 rowid；备份测试在恢复后的隔离数据库显式压缩 rowid，验证截止点不依赖这一实现细节，不能将其描述为本机 VACUUM 已实际重排。
