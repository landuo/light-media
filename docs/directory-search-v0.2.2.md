# v0.2.2 下载目录、监听整理与并发搜索

用户确认的操作是：资源下载或季订阅选择下载器和下载目录；监听任务根据独立目录规则整理到媒体库。此前下载时直接选择目标库的操作已更正。

## 配置与使用

1. 在“下载器”配置 qBittorrent 或 Transmission 地址、默认下载目录和路径映射。下载目录使用下载器看到的路径；映射后的路径是本应用可访问的位置。同路径可不填映射，但必须在已授权文件访问目录内。
2. 在“目录管理”建立规则，填写下载目录、应用源目录（不同路径时核对映射）、影视类型、目标媒体库以及硬链接/复制方式。选择“目录监听”或“下载器完成监听”并启用。
3. 搜索资源点击下载，选择下载器、下载目录，预览实际材料后确认。新建、编辑及多季订阅使用相同选择器；仍按季和起始集订阅。
4. 下载目录没有匹配规则、规则停用或不监控时仅下载。已选择规则的后台任务会在执行时核验规则及路径；规则被删除或改变时停止旧整理计划，界面保留原因。
5. 在“目录管理”查看连接/检查状态、监听文件和待处理数；有歧义时跳转文件管理人工整理，已执行结果在整理历史中查看。

新规则默认关闭监听。首次扫描默认把已有文件记为基线并跳过，后续新增或发生变化的文件才参与整理。需要处理已有文件时明确勾选“处理已有文件”。原 MoviePilot 的既有目录规则不会被自动启用或迁移。

## 监听语义

- 目录监听采用定期扫描和持久化文件快照，文件至少连续 60 秒不变后才识别。实际执行时间还受扫描周期和队列影响。
- 关联下载器的文件额外检查任务、每个文件完成率及实际大小；校验中、移动中、未完成或无法核对时不整理。独立源目录会核对路径重叠的已配置下载器；无关联下载器时依赖文件稳定性检查，无法判断未配置的外部程序是否暂时停止写入。
- 本应用发起的下载沿用已确认影视身份与季集，由完成核验流程处理，避免再次按文件名猜测或重复整理。
- 外部文件优先使用有效 NFO；否则要求文件名身份明确、TMDB 标题和年份匹配唯一。模糊身份、非标准编号、歧义及冲突进入待确认。修正 NFO 后会重新观察；其他问题可从文件管理人工处理。
- 整理计划与任务持久化；重启恢复不会重复发布。预览后和文件发布前重新校验规则、源文件、路径与目标，既有目标不覆盖。硬链接、复制及自动回退均保留源文件。
- 相同类型的启用目录监听不能在源路径上重叠或嵌套。源目录和媒体库目录也不能互相包含。
- 单轮上限 2,000 个视频、20,000 个目录项、16 层目录；超限明确报错而非只整理前半部分。每个相关下载器最多核对 200 个相关任务，超限需要拆分源目录。
- 下载器完成监听处理本应用已记录的下载任务；外部已完成文件使用目录监听或手动整理。旧版本已确认的任务保留原目标语义，新建下载/订阅使用目录规则。

## 搜索行为

影视资源搜索和关键词资源搜索均最多跨 5 个站点并发，同一站点仍串行且保留预算与认证冷却。每站完成即通过 SSE 返回结果并显示耗时，慢站不阻塞已完成站点。每站总搜索期限 45 秒，底层单次 HTTP 请求仍有独立超时。取消会中断请求并保留已经返回的结果。

这是实时搜索，不以历史结果代替新搜索。种子材料预览和文件核验仍在下载确认前执行。站点异常、解析不完整与超时会显示对应状态。

## 验证边界

新增离线回归使用隔离临时目录、合成文件及协议服务器，覆盖实际保存路径、季订阅持久化、无规则仅下载、目录基线、稳定性、完成检查、NFO 歧义及修正、规则变更阻止旧计划、硬链接源保留与重复扫描幂等。搜索测试以真实本地 HTTP 流证明慢站被阻塞时快站结果已到客户端，并核对取消传播和同站互斥。

浏览器、真实五站计时及 NAS 发布结果单独记录在同次发布验收单；不把协议回放等同于真实站点下载，不向既有种子或媒体库写入测试数据。
