## Native implementation and deliberate differences

Only fresh SourceUserStats parser provenance for hh-missing-panel, mt-invalid-json, mt-null-data and mt-invalid-integer can produce the event. A DTO with err_msg, connection tests (hooks=nil), arbitrary network/guard error, unsupported parser outcome, canceled operation, untrusted/reused error, or uncertain cold receipt cannot produce it.

The shared native parser Error() remains `site_user_source_module_failed`, preserving existing API/error-code behavior. SystemError.error and helper.text instead use four fixed safe Go-native descriptions containing the verified kind. This avoids merging four distinct failures into one helper dedup key without inventing Python exception text or adding note. Bodies, field values, cookies, API keys and machine absolute paths are never collected. traceback is explicitly labeled Go native parser diagnostic and contains only actual internal/sites Go function names and line numbers, captured at the registered parser failure. It is not a Python traceback.

The origin is read from the authenticated sealed collection and checked against the current job/API run and installation, site configuration, session/key scope and persisted settings within the transaction. API parameters cannot select a plugin owner. Native host jobs have no invented plugin instance owner.

A dedicated six-field SystemErrorEvent is stored with authenticated source evidence. DomainEvent gains only an exclusive system_error_id reference for system.error; mixed download/site/notice references and arbitrary payloads remain rejected. Event collection and batch reads resolve and verify the sealed typed evidence. Existing site.refreshed facts and successful DTO message routing remain separate.

To prevent rollback/revocation leaks, the source transaction stages MessageHelper first while holding its FIFO mutex, then records the typed event, then commits. Commit releases visibility; rollback restores both FIFO and short duplicate cache. This delays external visibility until transaction success compared with original immediate helper.put/send_event. There is no synchronous subscriber callback under that mutex and no external network call inside the transaction. Committed event evidence is durable; the UI FIFO is deliberately volatile. Crash after commit can therefore lose an unconsumed UI message, and neither restart nor receipt recovery reconstructs it. This preserves no-history/no-replay UI semantics rather than claiming exactly-once SSE delivery.

Only session-authenticated same-origin GET /api/system/message consumes the queue, including the /light-media mount. As an explicit SSE-only security narrowing beyond the fixed original endpoint, a nonempty Sec-Fetch-Site is accepted only for same-origin or none. In particular, same-site sibling-subdomain requests are rejected even without Origin, before touching the shared FIFO; SameSite=Strict cookies alone do not distinguish siblings. When Fetch Metadata is absent, a nonempty matching Origin is required in addition to the session cookie. Requests missing both headers are rejected before FIFO access because they cannot be distinguished from older-browser sibling-origin subresources. This also rejects legitimate older same-origin browsers which omit both headers; native EventSource cannot add the missing origin proof itself. No full-browser compatibility or workaround is claimed. Native HTTP clients without Fetch Metadata must explicitly supply the matching Origin. Explicit foreign Origin remains rejected regardless of Fetch Metadata. Global ordinary GET behavior is unchanged. No URL-token authentication, role filtering, cursor or Last-Event-ID replay is added. Session authority is checked before each frame. First frame is immediate, subsequent frames use the actual 3-second interval. Client disconnect, app stop, expiry/logout or write failure exits. A consumed message is not requeued after a network failure, matching destructive FIFO behavior.

UI adapts the existing bell to system/task tabs rather than a toast or second panel. Existing durable task notification API/read/jump behavior stays independent. System messages remain memory-only with local read state. One stream starts 3 seconds after login, closes after 5 seconds in background, and resumes in foreground. CLOSED manually retries at 3/4.5/6.75 seconds, while CONNECTING stays with browser-native retries. Logout, session-expired and unmount explicitly cancel timers, listeners, source and local messages. The small field guard/256KiB UTF-8 cap and blank rendering for empty or invalid dates are explicit display safeguards. Normal dates use the original frontend's fixed Day.js 1.11.13 relativeTime plugin with zh-cn, including its default thresholds, absolute-value rounding and calendar/DST differences; malformed date text is not claimed to be character-for-character compatible with the original formatter. The fixed version is evidenced by the original frontend commit's yarn.lock, not inferred from the previous Intl output. Source timestamps remain timezone-less local wall time, as in the source; frontend interpretation remains browser-local rather than fabricating a timezone.
