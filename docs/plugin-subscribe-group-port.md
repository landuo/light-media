## 已取证的原行为

- 状态为 `enabled OR category`，两个开关分别控制“下载后补空字段”和“按二级分类覆盖”。不能把 category 依赖于 enabled。
- 分类配置逐行用 `#` 分段，首个 `:` 分键和值；值中的后续冒号保留。分类和站点名称不 trim；站点仅从启用站点中按精确名称找第一个匹配。顺序、重复站点和空优先级组名称都不能擅自去重或修正。
- 同一分类后写覆盖前写。同一个长生命周期对象的非空重载会保留未重写的旧分类；空配置才清空缓存。原应用冷启动时缓存重新从当前配置建立。独立工作器不能在每次调用时无意抹掉活跃对象的缓存，也不能将旧缓存永久跨冷启动复活。
- 新增订阅按分类覆盖非空配置，包括关键词、站点、优先级规则组、分辨率、质量、特效和下载目录。`{name}` 替换为“名称 (年份)”。分类存在但所有选项都为空时，原版仍调用空更新并记录 `{}` 历史。
- 分类缺失时先通过媒体资料识别分类；识别不到即停止，即使配置中因尾随逗号形成了空分类键也不能填充。
- 下载事件先要求已保存的下载历史和有效上下文；只处理电视剧。单个 `Sxx` 限定季，空季或含 `-` 的范围查询所有季；非标准单季字符串按原行为失败。对每个匹配订阅只补空字段，不覆盖用户值；站点还须处于全局 RSS 范围。
- 制作组与自定义标记都存在时使用 `customization.+team`；只存在自定义标记时直接使用它。这是原有表达式，不自动转义成普通文本。
- 已处理键为 `电视剧:TMDB编号`，跨季共享。只在确有更新时写入；同一次下载更新多个订阅会追加重复键。不能改成逐季去重或无变化也标已处理。
- 分辨率匹配为前缀匹配；质量和特效的多个 if 顺序执行，并会对已经改写的结果继续判断。特效匹配使用原 Python raw string，替换值却是普通字符串，两者反斜杠数量不同。Go 分开保存两套字符串，未根据看起来合理的正则重写原规则。
- `clear_handle` 与 `clear` 在初始化时分别清除已处理键和显示历史，并回写对应单次标志。正式导入暂存仍不得自动消费这些标志。
- 历史内容保留 Python `json.dumps` 的字段顺序、空格及 ASCII 转义；详情按时间稳定倒序，单元格保持文本。原页面的 unicode_escape 解码也保留，包括旧内容直接含 UTF-8 字节时的实际显示差异。

## 已提交的核心入口

真正的新建订阅现在在同一 SQLite 事务中提交：订阅记录、创建时的影视身份密文快照、`subscription.added` outbox 事实。编辑已有订阅不再发一次“新增”。事件只含订阅/影视稳定引用，不携带路径、凭据或任意媒体 JSON。

该事件使用独立的 `purpose=subscription`、`subject_kind=subscription`；不冒用下载任务、资产或站点身份。读取私有快照需同时核对事件、订阅 ID 和影视 ID。延迟消费者拿到的是创建时的媒体身份；后来编辑所取得的新元数据不会重写旧事件。晚期 outbox 写入失败会回滚订阅和快照，用户可重新提交，不能产生只有半条订阅的状态。

事件订阅白名单已加入该类型；没有因此授予任何插件写订阅的权限。后续宿主处理仍须绑定实际交付批次、实例 generation/revision、当前订阅和允许字段，并将订阅更新、插件历史/已处理键及收据同事务提交。
