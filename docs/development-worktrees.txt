在对应工作树内运行该改动所需的检查，不建立额外的源码复制目录。
沿用默认 GOMODCACHE、GOCACHE 和 npm 下载缓存，不给每次测试创建专用依赖缓存。
依赖、锁文件及运行平台相同时可以复用已安装依赖。依赖变更使用该工作树自己的安装目录；不得在共享 node_modules 链接上运行 npm ci 或并发修改共享依赖。
前端源码改动后在同一工作树重建 web/dist，再构建嵌入该资源的 Go 程序，不能从另一个分支复制 dist。
web/dist 目前属于已有跟踪资产；其基线版本不等于新源码已构建。检查提交范围，不把临时二进制、测试数据库、日志和 node_modules 提交进去。
临时产物只放本任务 bin/、work/；测试数据目录和端口独立，不能连接生产数据库写入测试数据。
work/go.mod 是跟踪的目录隔离标记，使 go test ./...、go vet ./... 不递归编译临时 Go 草稿；work/ 下的其他文件继续忽略。
