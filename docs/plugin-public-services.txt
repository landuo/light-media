公共定时服务：原版入口与真实宿主接线
日期：2026-10-18
状态：本机、隔离 NAS 和真实页面验证通过；尚未部署，原配置与数据迁移为零。

入口与界面
右上角「捷径 → 服务」。对照 MoviePilot-Frontend 的 ShortcutBar、ShortcutToolDialog、ServiceView：使用原主题、服务卡片、60rem 弹窗、提供者/任务名称/任务状态/下一次执行时间/执行表格。小屏全屏，内容独立滚动，不新增左侧菜单或重复页面标题。
列表每五秒刷新，页面隐藏时停止轮询，关闭时释放定时器。执行请求提交成功后读取真实状态；等待或运行中的任务不可重复点击。请求失败明确显示错误，不把提交成功写成业务完成。

宿主和接口
GET /api/plugins/services：当前有效且已启用的插件服务，不返回私有调用参数、处理器、配置或凭据。
POST /api/plugins/services/run：明确提交 instance_id 和 service_id，沿用 enqueueManualPluginService、持久 occurrence/run、原 SDK 和每个插件的专属调度分支。手动执行不移动自动 next_due。
GET /api/v1/dashboard/schedule（亦支持 v2）：原版列表投影，直接返回 ScheduleInfo 所需的五个字段。
GET /api/v1/system/runscheduler?jobid=…（亦支持 v2）：只解析当前声明列表的完整 ID，不猜测下划线分隔；冲突时拒绝。此 GET 写操作仍执行同源/Sec-Fetch-Site 防护。所有入口均须管理员会话；未提供匿名命令执行接口。

显示边界
配置版本或安装代际已变、已停用、已卸载和已撤销的服务不显示。一次性服务被调度消费后，只要尚有排队、运行或待核对任务仍保留；终态后隐藏。真正执行中显示「正在运行」，同一安装代际存在待核对任务时，包含非定时的手动/API 任务，其服务均显示「等待核对」并禁用按钮；内部配置检查点变化不会掩盖这一状态，其他代际不影响当前显示；不伪装为仍在运行或已成功。时间按原版中文天/小时/分钟规则展示，不添加没有对应业务的百分比。
只展示已经注册的真实插件服务。系统服务尚未逐项接线，不能填充装饰行。PL-33 的命令、工作流动作、其他业务和完整进度仍需继续实现。

证据
冻结 2245 个输入，六个 Go 构建/验证步骤均 exit0，普通16项、竞态16项均无失败和跳过，默认生产构建、vet、Linux CGO=0 构建通过。前端142项通过，类型检查和生产构建通过。
实际编译的完整程序中，用一次性账号和本机词表验证「捷径 → 服务 → 执行 → 正在运行/禁用按钮 → 等待/恢复按钮 → 关闭重开」，源 HTTP 请求恰好一次，实际 SDK 执行成功。
相同冻结来源的 Linux 测试二进制在 NAS 的无网络、只读根、普通 UID、无 capability、256 MiB 限额容器执行16项，全部通过，无 OOM；另外核实容器和独占临时目录已经移除，现有 light-media/moviepilot/qb 的标识、启动时间、重启次数不变。
