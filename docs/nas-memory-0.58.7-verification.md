# 光影 NAS 内存复查（2026-11-23）

目标为常驻约 100 MB、峰值约 150 MB，同时尽量减少 GC。生产采样采用十进制 MB。主进程使用 `VmRSS` 和内核高水位 `VmHWM`。容器工作集使用 cgroup 的 `memory.current - inactive_file`，其最高值来自定间隔采样。带文件缓存的 cgroup 总占用和内核峰值单独记录。

## 已修复的分配路径

- 刷流和站点卡片查询最新统计时，从最新日期读取，找到最近成功日期后停止解密旧记录。当日更新按键读取该日记录。180 天加密历史的合成对照中，取得相同最新结果的累计 Go 分配从 2,047,764 B/op 降至 20,748 B/op，耗时从 7.03 ms 降至 0.093 ms。历史详情仍能读取完整历史，保留原有同日成功、失败和导入数据覆盖顺序。
- 站点 HTML 解析复用资源标记的字符替换器，避免反复收集只需首个匹配的节点。100 行 Nexus 合成页面的分配中位从 2,421,940 B/op 降至 997,125 B/op，资源内容、分页和登录校验回归通过。
- 目录监听只持久化本轮仍相关且完成核验的任务指纹。NAS 旧基线有 592 个指纹、载荷合计约 106 KB。需要重新出现的任务会重新获取文件，保留完成状态、归属及历史核验。

## Linux ARM64 归因与读池预算

生产 0.58.5 的一次 `smaps` 观测中，Go 堆映射约 89.7 MB，其中约 77.6 MB 由透明大页承载。用同一 0.58.5 程序进行六次独立测试，每次校验 1,000 个真实健康接口响应。关闭 Go 堆透明大页后，大页驻留中位由 27.26 MB 降到 2.10 MB，RSS 中位从 90.46 MB 到 90.64 MB，GC 各 8 次，保留 NAS 现有设置。在该样本上，关闭透明大页没有节省整体驻留。

SQLite 使用与生产一致的 modernc 版本。在 NAS 独占合成库上，对 96、320 和 540 个热页分别运行三组对照。每组启动新进程，四个只读连接各校验 3,500 次混合点查，随后核对全表扫描和 SQLite 缓存计数。每连接 2 MiB 改为 1 MiB 后，四连接预热的匿名 PSS 中位少 8.17–10.29 MB，各热集点查耗时中位变化约 +0.4% 至 +10.7%。在 540 页热集中，512 KiB 配置释放 SQLite 缓存后的匿名 PSS 高于 1 MiB 配置。生产候选采用每连接 1 MiB，保持四路读并发和原写连接。该预算直接约束 SQLite，Go 的软限额、GOGC 和归还节奏继续使用原有值。

2 MiB、96 页热集中，`PRAGMA shrink_memory` 后实际 SQLite 页缓存从 8.64 MB 变为约 20 KB，进程匿名 PSS 从 24.11 MB 到 12.66 MB，modernc 分配器保留约 19.92 MB 地址映射。应分开解释仍驻留物理页、分配器保留的地址范围与 Go 活堆。Go 内存软限额不计入外部映射。 [Go GC 指南](https://go.dev/doc/gc-guide) · [SQLite PRAGMA 文档](https://sqlite.org/pragma.html)

## 回归

ARM64 程序在 NAS 以独占数据和回环监听启动，校验四组目录合计 840 条观察及 1,000 个响应。站点、下载协议、文件命名和主程序测试通过。宿主定向通过站点读模型、导入账户行优先级、目录指纹、历史保护、GC 和读池测试。较宽的目录及文件管理测试有 27 项失败，用改动前的目录实现复跑，同一组 27 项仍失败。这部分没有作为上线通过证据。

## 实机窗口

上线前后使用同一容器与配置。窗口内后台任务负载自然变化，实机读数与受控分配实验分别解释。

0.58.7 另用 1 秒间隔采样 266 次，容器工作集中位 168.56 MB，采样最高 174.47 MB。该窗口原始 cgroup 占用中位 389.28 MB、内核峰值 406.79 MB，文件页和匿名页各自中位为 282.63 MB 和 110.51 MB。在一次同窗内的拆分采样中，文件页约 281.85 MB，其中活跃文件页约 51.23 MB。这能解释容器工作集为何高于主进程 RSS，单凭该数据还不能归因到某个文件或缓存策略。主进程、容器工作集均未通过 100/150 MB 目标。完成的窗口支持临时分配与 GC 改善，尚不足以判定长期增长趋势。
