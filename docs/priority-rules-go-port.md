## 已接通的行为

`internal/priorityrules` 内置完整原 22 项定义，自定义同 ID 规则整体覆盖内置定义。每次从当前配置建立独立快照，移除的自定义规则不会残留。规则组按配置表顺序选择，选择名称数组只决定成员，不重新排序。多个规则组串行过滤；后一个匹配组覆盖先前的优先级。未选规则组或不存在适用组时保持候选和原优先级。

表达式支持括号、`!`、`&`、`|`；`>` 以 100 开始逐层降级，命中即停止。优先级为零或负数仍是有效匹配。单层表达式按原 pyparsing 的前缀解析行为处理尾随文本及未完成操作符，不擅自改成全串解析。层级及条件惰性求值：已命中的高层不会被未访问的低层错误阻止，布尔短路也保留。Rust 行为的整链错误会按原包装器回退，从原输入重新计算，不能返回半份结果。

条件包括包含项 OR、排除项、指定字段/默认内容、标签、精确促销因子、最少做种数、发布时间及按集平均体积。大小采用 MiB，`>`/`<` 的边界实际为包含等号；区间两端也包含等号。发布时间单值表示至少多少分钟，区间按上下限；缺失/解析失败日期按原分钟值零处理。TMDB 条件命中直接通过整个规则项，其余约束不再判断；未命中再执行普通条件。媒体类型、二级分类、null/空字符串的适用性按原 RuleHelper 分支保留。

共享正则翻译器从既有识别词实现提取到 `internal/pyregex`，支持已核对的 Python 命名捕获/回溯引用和 Unicode 类语义，过滤采用忽略大小写。保留原识别词捕获顺序及超时选项；没有切换到会改变这些含义的 RE2 模式。现有 130 项原识别词样本另作回归。

真正的关键词搜索和影视搜索现在使用该内核。`priority_rules.search_groups` 是搜索默认值，`subscribe_groups` 是普通自动订阅默认值；`policy.filter_groups` 非空时覆盖各自默认值。首次进入搜索时冻结定义、名称、媒体信息及站点名称，后续设置修改不会改变正在执行的匹配。优先级参与当前候选排序，结束时发送已筛选的进度与最终结果；匹配失败清空候选并返回明确错误，不能把原始列表当匹配成功。

站点适配器独立保存标签和原副标题，规则直接匹配采集事实。现有展示副标题中的兼容标签不再需要被反向猜测为原数据。影视规则可取得二级分类元数据；标题搜索继续使用无影视身份的语义。体积规则按现有 Go 集数解析接线，明确编号但无法可靠解析时失败，未虚构集数。完整 MetaInfo 等效仍在剩余清单中。

配置通过已登录的规则分区 API 读写，密文保存于既有设置记录。通用设置 PUT 始终保留当前规则，避免旧系统/目录草稿覆盖新规则；实际关闭并重新建立 App 后可读取同一配置。字段为 `priority_rules` 下的 `custom_rules/groups/search_groups/subscribe_groups/source_mode/torrent_priority`，选择引用位于 `policy.filter_groups`。普通配置只接受原 CustomRule schema 的字段和类型；可信内置的 `match/tmdb/downloadvolumefactor` 不能由额外管理字段获得命令或宿主执行权限。

## 证据与限制

`testdata/plugins/priority-rule-original-oracle.json` 包含 202 组场景，分别取原 Python 和 Rust 入口结果，共 404 条对照；含 120 组固定随机种子的嵌套布尔表达式。其余覆盖优先级、顺序/覆盖、媒体适用性、回退、正则、标签、促销、体积、发布时间、错误与空值。全部比较匹配的原下标、优先级或原异常种类；内置定义也逐项比较。

参考生成只读取指定源文件并构造内存假对象，调用纯 Rust 函数，没有导入原应用、访问业务数据库或用户规则、请求站点、创建下载。发布时间使用合成时间；Python 大小分支的 MetaInfo 输入为指定合成集数，Rust 对相同合成标题实际解析。因此该样本不能代替完整 Go MetaInfo 解析或用户实际规则迁移的验证。

真实 Go App 测试使用合成站点 HTTP 协议，证明关键词筛选及优先级先于已有偏好排序、订阅和搜索默认值分离、显式选择覆盖、最终进度一致、失败清空、在途快照冻结、配置密文及实际重启持久性。搜索过程中没有抓私有种子材料或创建下载任务。规则快照还通过并发和取消检查。

首批内核的 Go 全量、modernconly 全量、受影响竞态、vet 和模块校验通过；该批没有修改前端。NAS 在 alpine:3.22、普通 UID 1000:GID 1001、只读根、network=none、cap-drop=ALL、no-new-privileges、256 MiB 内存、128 MiB tmpfs 下分别执行规则、实际 App 搜索/持久性和原识别词回归，只挂载合成样本及测试程序。

## 继续保留的交付项

- 原版独立的“规则测试”系统工具。它需要真实 MetaInfo 和媒体识别结果；规则设置页不额外添加自创测试入口。
- `TorrentsPriority` 已接通四项排序及现有解析器的季集计数；多季包等完整 MetaInfo 的计数与所有标题结构仍需补齐，不能把排序键的合成对照当作完整解析等效。
- BestVersionFilterRuleGroups 的洗版默认分支；当前是普通搜索/订阅默认值。
- 完整 Go MetaInfo 和自定义资源标记/官组，以及所有所需集数表达式的源码对照。更广泛 Python 正则构造也需按实际原规则逐条核对，不能把 404 条合成结果当作任意模式完全等效的证明。
- 规则失败已有规则组、层级和规则 ID 定位；仍需和独立规则测试工具联调。
- 原用户规则、组顺序、默认选择与行为设置正式迁移；站点元数据、配置及引用的实机核对。
- SubscribeGroup 的宿主授权、真实订阅写入、历史/已处理键/收据事务、配置/历史页及正式迁移。

以上仍属于原定范围。规则内核及搜索通过不等于 SubscribeGroup 已注册、已可用或已迁移；正式服务没有切换。

## 规则管理界面与排序接线（后续批次）

原版 UI 参照 `AccountSettingRule.vue`、`CustomRuleCard.vue`、`FilterRuleGroupCard.vue`、`FilterRuleCard.vue` 和三个编辑/导入弹窗。新项目“设置 → 规则”保留三个独立分区及各自保存按钮；自定义规则、规则组和组内优先级使用原版同版本 `vuedraggable@4.1.0`，沿用 Vuetify 3.7.3 主题。规则编辑宽 40rem，组编辑宽 80rem，小屏全屏，内容独立滚动、操作栏固定。图标来自原模板的 filter/filter-group SVG。

新增/删除/排序、编辑弹窗确定和代码导入先改本分区草稿，只有分区保存才持久化。导入兼容原版 JSON 数组，追加规则或规则组、丢弃原 schema 以外字段；组内表达式导入替换优先级卡片。分享复制 JSON 或表达式，不改成配置文件下载。内置项的空格、表达式拆分及自定义同 ID 覆盖的原前端判断行为均保留。已访问设置页签的草稿独立保留；保存一个区不刷新另一区草稿。媒体类别来自当前独立分类策略，不硬编码类别。

`GET /api/settings/rules` 提供配置、各分区版本和分类选项；`PUT /api/settings/rules/{custom|groups|priority|defaults}` 接受 `{revision,value}`。三个 UI 分区分别对应前三项，defaults 保留给搜索/订阅默认选择接线，规则设置页没有新增原版不存在的默认选择控件。版本比较、密文配置和变更版本在同一 SQL 事务提交；内部可信设置写入也会更新对应版本。旧版本返回 409，不刷新版本并自动重试覆盖。SQL 故障、其他分区保存、旧通用设置草稿和实际 App 重启均有测试；接口沿用登录及同源检查。

下载排序已接入影视身份搜索和普通自动订阅结果。按原 `TorrentHelper.sort_torrents` 拼接媒体标题、选定次序的资源优先级/站点优先级/站点上传量/做种数，再拼季集数量；反向稳定排序。Python 字符数填充、不截断宽值、负数的字符串顺序也保留。空选择保存为空，但排序时按原后端回退 `torrent/upload/seeder`，不会自行解释为关闭排序。上传量按账户快照名称匹配；凭据变动后沿用新项目既有的快照失效检查。诊断性拒绝行仍置于可接受行之后；无身份关键词搜索保留当前偏好排序，不套用原版只在影视搜索调用的完整排序。

排序参考只读提取 NAS 已安装 `app/helper/torrent.py` 的纯方法 AST，用合成 Context/站点统计替代依赖，未导入原应用、读取用户配置或启动旧任务。源 SHA-256 为 `1c8a420d419ee53579079283ea0828536de9d978b6b15e722f1ba53cb51d5dd5`；88 组样本（含 80 组固定种子的排列）逐条比较完整排序键和输出顺序。样本为 `testdata/plugins/torrent-sort-original-oracle.json`，SHA-256 为 `56c8c04eb04d68879c54e229e68e84a10eafed0f81c9fe53f89ea50d6d12db46`。
