SeedRescue 历史导入校验修复（2026-10-21，尚未正式迁移）

本次修复原版稀缺保种历史写入后无法被 Go 插件读取的问题。原导入流程仅保存了加密 KV，没有同时更新所有权记录中的数据修订、摘要及其根记录，导致读取时返回 SEED_RESCUE_EVIDENCE_MISSING。现在先校验新安装实例的所有权记录，再在导入事务内保存数据及相应修订/摘要、更新根记录，最后提交迁移收据。数据、所有权记录、根记录及收据任一写入失败均整体回滚；没有重新初始化或绕过校验。其他插件的导入数据及收据摘要算法保持原样。

验证分为合成与原版真实数据两部分。合成用例覆盖约 3 MB / 1140 条记录、重启读取、重复导入保留用户修改、另一个实例不受影响，以及数据/所有权/根/收据写入失败和根记录损坏或缺失。相关应用普通和竞态测试各通过 85 个顶层用例（含子项 156 个）；两个跳过项为独占下载器联调和需 stdin 的原版数据用例，后者另行执行。

原版 3 项 KV 共 2,934,138 字节（jobs 2,923,784；rss_snapshots 10,126；scan_status 228），只通过内存与 stdin 传入自建临时加密数据库。普通和竞态执行均证明：重启后所有权校验通过，KV 原始字节不变，当前/历史列表分页合计保留 1140 个任务身份，5 个下载中、7 个等待 IYUU、104 个等待选择等状态没有变化。此验证使用只读业务投影；不包含实际站点、下载器宿主绑定或生产 UI 验收。没有启动扫描、下载或定时任务，没有修改原版或生产新程序。

另已只读核对：历史/配置涉及的 17 个原版站点均在新程序找到唯一规范地址对应项；11 项 Cookie 相同，6 项已有变化，17 项 API Key 对应一致。下载器地址、账户和密码对应一致。后续使用新程序当前凭据，不能用旧值覆盖用户修改。此核对不是连接测试，也尚未写入站点/下载器引用映射。

原版扫描明确要求已安装且启用 IYUUAutoSeed。该依赖尚未迁移；还需完成原编号命名空间、稳定下载器绑定、独占扫描/下载/恢复联调、实际界面和正式迁移。当前实际完成仍为 7/23，生产仍为 0.4.8；不能将本次历史导入验证计为第 8 个插件完成。
