01 · 目标与已确定范围

做一个供个人 NAS 使用的影视自动化工具：从发现作品、挑选资源到下载、整理、刮削，再进入飞牛影视。采用 Go 后端 + Vue 3 / TypeScript 前端 + SQLite，以一个应用进程承担业务。

本方案是新项目设计基线，不是在旧 Go 项目上继续堆功能。MoviePilot v2 和已有 Go 项目仅用于理解行为、发现边界与设计测试用例。本次交付方案文档，没有修改旧项目、部署服务或操作下载器。
项目设计基线
已确认：资源站点馒头、憨憨、UBits、家园、1PTBA，全部列入首版交付范围；采用原生适配。
已确认：媒体库飞牛影视。首版包含目录/NFO兼容与飞牛连接、库同步/刷新适配。
已确认：存储边界只做本地/NAS 目录，用户明确不需要云盘；不增加云盘上传、挂载或原生云存储适配。
已确认：产品体验选择影视 → 订阅或搜索 → 筛选资源 → 下载 → 识别整理 → 刮削入库；同时提供榜单、演员资料和相关推荐。
已确认：下载器P0 同时支持 qBittorrent 与 Transmission；可配置多个实例，订阅/手动任务指定目标下载器。Memos 记录的已有服务仅为部署参考，本次未检查运行状态或版本。
已确认：插件路线P0 预留版本化接口、事件及下载器种子与文件的关联；P1 实现插件运行与管理，并交付辅种、转移做种插件。不增加独立做种模块，持续做种由下载器负责；首版核心不依赖插件运行器。
已确认：自动化边界P0 保存按剧集号映射；区分主动移除、真实缺失与存储不可用；主动移除默认不再自动获取或整理回库；提供重启后仍生效的全局自动化暂停。具体规则见第 7、9 节。
建议：部署形态NAS Docker 单副本，Linux amd64/arm64；浏览器访问，自适应桌面与手机。开发环境可在 macOS。
待实现前确认五站实际访问域名、NAS CPU/内存、目录及文件系统布局、qBittorrent、Transmission 与飞牛影视版本；这些不影响本稿的总体架构。

“不用 Python”能减少解释器与相关依赖，但不能单凭语言保证省内存。该项目的主要手段是：减少常驻服务、限制并发与缓存、按需请求、流式处理文件。文中的性能数字均为待实测的验收目标。

02 · 首版需求与取舍

P0 是首个可用版本必须具备的内容。下面包含必要的可靠性功能；没有它们，自动下载会变成需要频繁人工清理的半自动工具。

编号P0 功能具体行为与完成标准
FR-01影视发现电影/剧集搜索；趋势、热门、高分榜单；卡片标注“已入库、已订阅、下载中”；能进入详情。榜单显示来源及更新时间。
FR-02详情与相关推荐标题、年份、简介、海报、评分来源、演员、季集信息；提供搜索资源/订阅入口，展示同作品的相关推荐。
FR-03演员资料头像、简介、出生信息等已有字段；出演电影与剧集，按年份/热度排序；缺失数据明确留空，作品可继续搜索或订阅。
FR-04五站原生接入逐站连接检测、认证、搜索、解析资源属性、获取种子；站点故障单独显示。支持的站点增加增量订阅入口，其余走限额搜索。
FR-05资源搜索用已确认作品的外部 ID/别名/年份搜索；分站渐进返回、分页、来源去重；能取消搜索；区分“无结果”与“站点失败”。
FR-06资源筛选分辨率、来源、编码、HDR/DV 标签、语言/字幕标签、体积、做种数、免费状态、包含/排除词；硬过滤与偏好排序分开，展示命中/排除理由。
FR-07电影订阅无合适资源时持续等待；有已入库文件则不下载；支持暂停、恢复、立即检查和终止；成功入库后完成。
FR-08剧集订阅按季、起始集/指定范围订阅；追更模式允许目标集增加；准确记录已有、下载中、待整理、缺失、未播；每部剧独立设置查找计划，不能仅靠总集数判断。
FR-09双下载器与多实例管理P0 支持 qBittorrent、Transmission；连接与能力检测、目标实例选择、添加/暂停/继续/校验、状态同步、文件列表与完成确认；默认仅管理本程序创建或用户明确接管的任务。下载完成后的做种状态继续显示在原下载器种子记录中，不新建独立做种任务。
FR-10身份识别与纠错使用下载时绑定的作品身份与季集；解析本地文件名/NFO；歧义进入待确认；人工修正后直接重试原任务。P0 支持保存按剧、编号范围限定的集号偏移/逐集对应规则，预览后用于后续匹配，详见第 7 节。
FR-11自动与手动整理独立“手动整理”入口，选择单文件/批量目录，无需下载记录；识别与人工修正、目标路径预览、权限/空间/冲突检查；硬链接默认，复制显式选择；保留源文件。
FR-12基础刮削电影 NFO、tvshow.nfo、单集 NFO、海报/背景图；已有字幕旁车按同名规则关联；失败项独立补齐。
FR-13飞牛影视适配连接/版本能力检测、选库与路径映射、读取已入库信息、整理后请求/等待扫描及结果核对；API 兼容失败时可见地降级，不能假报成功。
FR-14既有库导入首次只读扫描现有媒体及 NFO；人工确认不确定项目；正确建立已有集集合，避免把旧库当空库重新下载。
FR-15任务持久化与恢复进程重启后继续未完成任务；下载请求超时先核对；整理半完成可恢复；外部服务断线不会清空占位。
FR-16基本运维单管理员认证、配置向导、连接检测、错误中心、站内通知、数据库迁移和一致备份/恢复。
FR-17日志系统与问题排查独立日志中心：实时查看、历史检索、级别/模块/站点/任务过滤；任务全流程时间线；结构化开发日志、临时 DEBUG、脱敏导出、轮转与日志故障提示。详见第 10 节。
FR-18追剧日历与自定义追更计划周/月日历展示订阅更新与获取状态；支持元数据日期、自定义每周/每日/每 N 天周期、单次停更/延期；分别设置资源检查间隔、活跃时段和补漏检查。详见第 7 节。
FR-19插件扩展基础P0 保留下载器能力接口、种子材料引用、种子与文件关联、多实例身份及版本化事件；区分获取/辅种/迁移目的。P1 插件运行器与业务插件使用这些接口，详见第 14 节。
FR-20移除、缺失确认与补获取主动移除需预览文件范围并选择后续策略，默认“不再自动获取”；外部删除确认后默认等待处理；存储不可用保留原资产状态。排除规则覆盖自动下载与重新整理，可显式解除；不删除下载器种子或做种源文件。
FR-21全局暂停自动化暂停新的自动搜索、下载提交、整理及后续自动写入/刷新；执行中操作在安全步骤停下，已发请求先核对。状态持久化，恢复时合并补查；下载器已有种子的运行不随此开关改变，详见第 9 节。
阶段范围
P1：已确定要做插件安装/启停/配置/版本兼容/日志/任务管理；辅种插件、qBittorrent ↔ Transmission 转移做种插件。
P1：其他候选增强质量自动升级、多版本保留；复杂动漫编号的自动推断与剧集组适配（P0 已有人工保存的集号映射）；字幕自动搜索；qBittorrent/Transmission 以外的下载器；更多榜单来源；Webhook 通知；旧系统数据导入工具。
当前仍不包含公共插件市场与自动更新、AI 对话/Agent/MCP 服务、通用工作流编辑器、云盘/网盘整理、自动签到/刷流、自动删数据、播放转码、社交系统、多租户权限。插件能力不等于默认开放以上功能。
无需另造的能力BT 下载、校验与持续做种交给 qBittorrent / Transmission，播放与转码交给飞牛影视；应用保留自己的 API、认证、调度器和持久任务。不增加独立做种页面或每个种子常驻的做种后台任务。

基础发现功能已经是你的明确需求，所以榜单、演员和相关推荐是 P0。个性化推荐算法、豆瓣专属榜单、演员自动订阅则不在首版范围。

页面用户能完成的事
发现切换电影/剧集榜单、搜索作品；查看缓存时间；识别哪些作品已经在库中。
影视详情看简介、季集、演员及相关推荐；选择电影或某一季，点“搜索资源”或“订阅”。
演员详情阅读资料、浏览出演作品；进入作品详情形成连续浏览。
资源结果看来源与质量、免费有效期、做种数、筛选解释；选择资源及目标集，查看下载预览。
订阅查看缺集/待播/在途/入库/排除/缺失待确认情况，调整质量策略、集号映射，暂停或立即检查。
追剧日历按周/月查看哪天预计更新哪些订阅，标注元数据/自定义/预测来源及在途/入库状态；进入订阅调整更新规律和资源查找计划，显示下一次实际检查时间。
任务分别显示下载、待确认、整理、刮削、飞牛同步；失败任务提供原因及就地重试。
媒体库与待确认查看本地资产，导入已有库，处理识别歧义、季集冲突、文件冲突；预览主动移除范围，选择是否补获取，处理外部缺失及解除排除。
手动整理选择文件或目录，逐项识别和修正影视/季集，预览后只执行选中项目；不依赖下载器记录，失败项目可单独重试。
日志中心实时跟随/暂停，查询历史记录，按时间、级别、模块、站点、任务或关键词过滤；从失败任务直接跳到对应日志及完整时间线，导出脱敏诊断包。
设置站点凭据、qBittorrent/Transmission 多实例、TMDB、飞牛影视、每个实例的路径映射、策略、备份。
全局状态栏显示自动化运行中/正在暂停/已暂停；操作暂停或恢复，展示仍在收尾、待核对的操作。手动搜索可用，暂停期间手动提交下载/整理等写操作提示先恢复。
插件（P1）本地插件包安装、版本与接口兼容检测、启用/停用、配置、授权范围、手动执行、计划任务及日志；辅种/转移先展示计划与校验结果。
榜单 / 搜索 / 演员作品→影视详情→手动搜索或订阅→筛选并解释→qBittorrent / Transmission→识别与整理→NFO / 图片→飞牛影视可见

手动路径：选作品 → 搜资源 → 查看通过/拒绝理由 → 确认下载 → 在任务页看进展 → 文件入库并出现在飞牛影视。自动路径：选作品/季 → 选质量策略 → 创建订阅 → 定时或增量发现资源 → 自动决策 → 同一后续流程。

手动整理路径：选本地文件/目录 → 扫描识别 → 修正影视与季集 → 预览目标路径和冲突 → 选中项目执行硬链接或复制 → 刮削 → 飞牛入库。批次和每个文件都有任务 ID，可在日志中心分别追踪。

人工操作的反馈要落在业务问题上，例如“已有 1–6 集，这个包包含 1–12 集，需确认额外下载”，或“文件季号为 S02，与订阅 S01 冲突”。不要只显示异常堆栈，也不要把技术重试当成下载成功。

04 · 技术栈与模块边界

层选择原因与约束
后端Go，稳定受支持版本网络请求、任务调度和文件操作集中在一个进程。使用标准库 net/http、context、database/sql、slog、embed；按模块组织，不拆微服务。
前端Vue 3 + TypeScript + ViteSPA 静态构建，嵌入 Go 二进制；生产不运行 Node 服务。采用现成组件库，重页面交互按路由懒加载。
数据库SQLite WAL单写连接 + 少量读连接；短事务、唯一约束、迁移文件；不加入 Redis/MQ/PostgreSQL。
SQLite 驱动先以纯 Go 驱动验证，保留 cgo 对照modernc.org/sqlite 与 mattn/go-sqlite3 在原型阶段用相同数据跑基准，再固定其中一个；不维护两套生产实现。
协议适配Go net/http + JSON/XML + HTML 解析优先站点 API；HTML 解析采用维护中的 Go DOM/选择器库。五站共享 HTTP、限流和标准模型，站点差异单独实现。
后台任务SQLite jobs 表 + 有界 worker内存只保存唤醒信号和小批任务；任务可恢复，不为每个订阅创建永久 goroutine。
日志slog + 有界输出器 + JSONL 轮转文件网页日志中心读取应用自己的日志文件；关键任务事件和操作记录保存在 SQLite。不新增日志服务器，日志级别与详情可控。
外部组件qBittorrent / Transmission + 飞牛影视 + TMDB复用现有服务。ffprobe 如后续需要，按需启动并计入资源预算；首版不依赖 Python 或常驻浏览器。

为何选 Go：它在维护成本、部署便利和运行资源之间适合这项以 I/O 为主的工作。Rust 是合理备选，尤其在你已有 Rust 经验或内存预算极紧时；仅仅没有 GC，并不保证整个应用更省内存。TypeScript/Node 适合快速开发，但与当前低常驻占用的目标相比，Go 更适合作为本稿默认选择。这是工程判断，不是性能测试结论。

05 · 五站原生适配策略

五站均为首版交付目标，但“已经在 MoviePilot 中支持”不等于“新程序已经通过联调”。本次未登录这些站点，域名、认证和返回格式需要在原型阶段逐站确认。

站点接入路线首轮验证重点
馒头 / M-Team专用 API 适配器；使用 API Access Token，经 x-api-key 发送。搜索、外部 ID 查询、种子下载令牌、促销信息、限额。官方明确要求第三方工具用 API Token；不用 Cookie 登录接口代替。
憨憨独立适配器，共用 NexusPHP 类 HTML 解析基础；参考源码包含 hhanclub.net 与专用解析器。实际域名、Cookie 会话、登录判定、资源表格与免费标签、下载入口；不假定与标准模板完全相同。
UBits独立适配器；复用适合的页面解析基础。搜索参数、分类映射、分页、促销标记和种子链接；字幕/音轨标签是否可靠。
家园以实际 URL 确认站点身份，再确认页面/API；候选为 NexusPHP 类解析路线。不要把“家园”直接等同 HDHome；如指 PTHome，使用对应域名与样本。确认搜索语义、资源 ID、促销有效期。
1PTBA独立适配器；参考源码指向 1ptba.com、Cookie 页面体系与 index.php 登录检测。认证测试不能假定所有站点都使用同一个 torrents.php 页面；搜索/下载选择器需当前样本验证。

馒头路线依据 馒头官方 API 说明 与 MoviePilot 馒头适配实现。憨憨见 专用 Nexus 解析器，1PTBA 见 站点连接检测。这些是固定提交的源码证据，当前域名/认证/页面细节仍须联调；UBits 的域名与模板没有在本次源码中确定，不猜测填入。

标准资源包含：站点与资源 ID、标题/副标题、发布时间、体积、做种数、促销状态与过期时间、外部作品 ID、解析后的季集/质量标签、可用字段及原始证据。未知字段保存为未知，免费信息缺失不能当成免费。

  • 鉴权数据只在后端使用。Cookie/API Token 按站点隔离；下载令牌临用获取，不作为长期稳定 URL 保存。可由应用获取 .torrent 后提交给所选下载器，避免将整份站点会话交给下载器。
  • 下载前重新核对资源与促销状态。“仅免费”表示决策时满足条件；若不确定或已过期则停止该候选。促销可能在下载中变化，界面展示有效期，首版不通过自动删种兜底。
  • 每站同时只发 1 个请求；设置超时、响应体/页数/结果上限、重试退避、429 冷却和认证失败提示。公开 HTML 不能成功解析时返回“协议变化”，不返回假空列表。
  • 优先按站点拉取新资源，再匹配多个订阅；无可靠增量入口时，按作品合并查询并执行缺集搜索。暂停、未到检查时间和已完成订阅不占搜索配额。
  • 维护每日站点预算，手动搜索保留额度。馒头官方当前建议搜索上限为近 24 小时 1000 次，详情请求及下载种子各有单独限额；本稿建议先设 600 次/日搜索预算，所有翻页、别名、重试和增量查询一并计数，后续按实测调整。
  • 不能为 200 个订阅每隔数分钟轮询全部五站。普通补漏检查从 4–12 小时起步；剧集预计更新后的短时活跃窗口可提高检查频率，但仍受站点配额、去重、冷却和每日上限约束，详见第 7 节。实际检查时间与延期原因在界面可见。
  • 登录或搜索遇到浏览器挑战，先报告当前会话不可用，进入人工更新凭据/适配修复；不悄悄启动 Chromium。若某必需站点只能经浏览器运行，先重新评估资源成本和方案边界。

每站保留脱敏 JSON/HTML 样本：正常、空结果、认证失效、分页、免费与过期、错误响应。每站至少完成“搜到作品 → 获取真实种子 → 加到测试下载器”的合同测试，才标记为支持。

06 · 发现、演员、相关推荐与刮削数据

首版统一用 TMDB 作为元数据主源。内部作品身份使用 内部 ID + 媒体类型 + 来源 ID，电影和剧集不能只用一个裸数字合并。下载任务从创建时就携带已确认身份，避免下载后重新猜片名。

能力实现方式体验与缓存建议
影视搜索/详情中文、原名、别名、年份；电影/剧集分开；保留 IMDb 等辅助 ID。默认 zh-CN，缺字段回退原始信息；人工修正字段不被自动刷新覆盖。
推荐榜单趋势、热门、高分；按来源分别命名。趋势/热门初始缓存 1 小时；高分 6 小时；显示更新时间。不是豆瓣榜单，也不冒称个性化推荐。
演员资料人物详情 + combined_credits；以人物 ID 关联。资料建议缓存 7 天；作品表按需刷新；没有照片或中文简介时显示合理占位。
相关推荐电影与剧集各自的 recommendations 接口。建议缓存 24 小时；无结果显示空状态，不用随机列表冒充相关推荐。
季集信息维护季、集、播出日期、剧集状态及更新时间。连载作品至少每日更新，并在检查订阅前按需刷新；不能假设首次取得的集数永不变化。
海报与刮削请求适当尺寸图片，落磁盘缓存；按资产生成 NFO/旁车图片。不在内存里保存整部剧的全部大图，不遍历演员再递归预取其所有作品。

接口依据：TMDB 趋势接口、TMDB 人物资料、TMDB 人物影视作品、TMDB 电影相关推荐、TMDB 剧集相关推荐。

以上 TTL 是初始配置，不是数据源承诺。缓存键含来源、语言、类型与 ID，缓存保存获取时间和版本。TMDB 故障时优先使用缓存；缺足够身份/季集证据则等待或交给人工确认。已确认文件的整理可以继续，刮削单独重试。

TMDB Token 仅配置在后端；遵守限速反馈，遇 429 退避。关于页面按要求提供 TMDB 署名；若未来商业化，重新确认授权条件。参见 TMDB 限速说明、TMDB 使用与署名说明。

刮削最低输出：电影 影片名.nfo、poster.jpg、fanart.jpg；剧集 tvshow.nfo、每集同名 NFO 与剧集图片。飞牛是否优先读取所用 NFO 文件名、ID 字段和演员数据，通过实际版本的样本库确认；不把写出 XML 等同于已被飞牛正确读取。

07 · 订阅、筛选和下载的正确性

追剧日历与每部剧的更新规律（P0）

日历回答“哪一天预计有哪部剧更新”，检查计划回答“程序何时去站点找资源”，两者分开保存和展示。播出不代表站点立即有资源；调整检查频率也不应改掉日历里的播出日期。

设置支持内容语义
更新规律来源跟随元数据 / 用户自定义保留元数据原值、来源及更新时间；自定义设置只覆盖本地日历计划，可一键恢复跟随。
自定义更新规律每周指定一个或多个星期、每天、从起始日期每 N 天；时间可选，时区默认 Asia/Shanghai。适合每周五、一周双更或隔日更新；仅有日期时显示“时间待定”，不虚构午夜为真实播出时间。
单次例外本次停更、本次延期、指定日期加更；也可设停更到某日期。可以只改本次或从某日修改后续规律；本次跳过不自动平移后续所有集数。
资源查找计划跟随预计更新时间 / 固定间隔 / 仅手动；设置发布后等待时长、活跃窗口与窗口内间隔。每部订阅单独配置。全局站点配额及认证冷却优先，不保证设 30 分钟就能绕过限额准点查询。
窗口后补漏活跃窗口未找到时降低频率继续查缺集，可设置追查期限和到期提醒。不能周五没有资源就一直等到下周五；已入库或有效在途目标停止重复查找。
日历展示周/月视图：海报、片名、已知季集、预计日期、计划来源、待播/待资源/在途/入库状态。显示最近检查和下一次检查；周规律推算的条目标“预计更新”，没有可靠集号时显示集号待确认。

以“绝世唐门每周五更新”为配置示例：用户填写星期五，若知道发布时间可再填时间；例如设置 18:00（仅演示，不是对实际播出时间的核实），等待 30 分钟后开始找资源，6 小时内每 60 分钟检查；尚未找到则每 6 小时补漏，48 小时后提醒并继续低频检查或按用户规则暂停。最近一次检查、下一次计划、实际因配额延迟的时间分别可见。

  • 日历计算优先级：单次人工例外 → 生效的用户更新规律 → 元数据播出日期。三个来源分别保存；元数据后来改变时提示差异，不能静默覆盖手动设置。
  • 日历中的周期性“预计更新”只用于展示和安排检查，不能凭经过一个星期就创建一个已播剧集、增加总集数、认定缺失或已完成。自动下载仍需要已确认作品/季集和资源覆盖证据。
  • 需要更正某一集实际可获取日期时，单独保存该已知剧集的人工日期/提前获取授权；这才影响下文 A 集合。普通周历预测不等于允许下载未播内容。
  • 只暂停本次更新对应的查新任务，不取消正在下载/整理的任务，也不阻止此前已确认缺集的低频补漏。全订阅暂停则停止新获取，已有任务遵循独立取消规则。
  • 有共享 RSS/站点增量信息时继续按缺集和资格规则匹配，更新窗口主要控制主动搜索频率，不将“周五更新”当成其他时间所有资源都必须拒绝的硬过滤。
  • 日历有时间区间边界，按需生成可见范围；不为每个未来周次永久注册任务。jobs 记录最近到期的检查，schedule_revision 使修改前的排队计划失效；领取和外部请求前重新校验暂停/版本状态。
  • 程序停机错过多次检查后，恢复时合并成一次必要补查，不把所有过期轮次瞬间补发。时区转换、跨午夜窗口和日期型元数据分开处理；重启不丢失用户周期和单次例外。
  • 检查计划保存时预览未来 5 次预计检查及配额影响。单站/全局预算、退避与手动操作保留额度仍生效；日志记录“为何现在检查、为何延后、使用哪个计划版本”。

与本次参考的 MoviePilot v2 的区别：订阅模型及公共输入未定义单订阅的星期/播出时间/自定义检查周期；日历缓存预热媒体源信息和 TMDB 分集信息；全局调度分别控制搜索补全、站点刷新及 RSS 间隔。因此“可设置全局刷新间隔”不能等同于“可修改某部剧的更新规律”。这是固定提交的核心实现结论，不代表验证过所有插件或用户实际安装版本。

按集合判断缺集

T = 用户目标集（追更模式可随元数据增长）
A = 已播出或用户明确允许提前获取的集
L = 本地已确认存在的集
P = 有效下载意图、下载中、下载完成待整理的集
E = 用户明确排除自动获取/自动整理的集
H = 文件缺失待核对或待用户决定如何恢复的集
N = (T ∩ A) − L − P − E − H   # 本轮可以自动找的集

未知播出日期不能直接当成已播；固定范围订阅在全部目标入库后完成，持续追更订阅需要已确认该季结束或用户主动结束。整理失败保留占位并重试整理；下载终止经核对后才释放占位。下载器离线不等于任务消失。

E、H 是资格控制，不是已入库事实；界面单独展示“已排除”“缺失待确认”，不能算进已下载/已入库数量，也不能据此将未满足目标的订阅伪报完成。电影采用同样的作品级控制；全局暂停和单订阅暂停仍在此集合计算之外控制执行。

按剧保存集号映射（P0）

人工纠错分为“只修正本文件”和“保存规则供后续使用”。规则绑定已经确认的作品身份与目标季，限定原始编号区间；可进一步限定站点/发布组/命名形式，不能把某部剧的偏移变成全局规则。搜索资源覆盖与文件整理使用同一规则版本，并分别保留原始编号和标准季集。

边界确定行为
首版支持编号区间加固定偏移，或逐集对应表；保存前展示原始编号 → 标准季集及冲突。示例 101–112 → S02E01–E12 仅演示规则，不代表《绝世唐门》的实际季集结构。
适用与歧义单文件明确纠错优先；范围内、来源条件匹配的已确认规则其次；其余采用无歧义标准编号。多条规则冲突、范围外编号、特殊篇、未知目标集或身份不一致时进入待确认，不猜下一集、不凭映射认定已播。
自动流程复用资源搜索、下载文件范围与入库命名均从原始编号转换一次；保存 mapping_id / revision 与原始证据，避免对已经标准化的编号再次加偏移。
修改与历史规则保存需预览；影响尚未提交的候选/计划时重新计算和核对占位。已经提交下载或入库的记录保留原快照，修改规则不自动重命名源文件、改写历史或重新下载；需要重整理由用户单独预览执行。
P0 / P1 分界P0 允许用户确认后持续复用规则；跨来源自动推断、复杂剧集组适配仍是 P1 候选。TMDB 刷新不覆盖人工规则；目标结构变化时提示复核。

主动移除、外部缺失与补获取（P0）

情况默认行为与恢复方式
在应用内主动移除先展示具体媒体库文件及受影响电影/季集，再选择“不再自动获取”（默认）或“允许补获取”。只涉及明确选中的媒体库文件；不移除下载器种子、不删除做种源路径，不递归清理整目录。
不再自动获取持久保存作品/季集级排除 E，拦截自动下载和从源文件自动整理回库；不只是暂停当前订阅。新建/重建同作品订阅也须尊重排除，未来未被排除的集可继续追更。
允许补获取只有用户明确选择且对应排除已解除才进入恢复流程；先核对其他在库副本、下载中任务和完整源文件，优先恢复整理，确无可用内容再按订阅策略搜索。没有有效订阅时明确新建恢复意图，不能让按钮承诺无人执行的补获取。
在 NAS/飞牛等外部移除无法从文件消失推断用户意图。完整扫描并复查确认缺失后进入 H，默认等待选择“恢复整理/允许补获取”或“不再自动获取”；其他正常内容继续工作。
挂载掉线 / 权限错误 / 扫描中断标记存储或扫描异常，保留此前资产与去重事实，不按空库补下载。挂载恢复后只在完整、成功的扫描范围中重新核对。
解除排除 / 手动再次获取必须显式选择；展示涉及的作品/集、现有源文件及在途任务。仅点“立即检查”、重试旧任务、重建订阅或重启不能隐式清除排除；手动下载/整理也不能静默绕过提示。

排除按稳定作品/季集身份保存，跨订阅生效；作品/季范围与单集范围需在确认页清楚区分，不能因移除一集就排除整部连载。多集同文件不能只删除其中一集，预览必须显示全部受影响集；其他副本仍存在时不把这些集标为缺失。排除不隐藏真实文件，也不把仍在库的作品假报为空。

移除是有预览和操作记录的显式动作。先持久化操作意图及选定策略，再按当前文件身份和授权路径执行；若路径与做种源路径重合或经链接解析到源路径则拒绝。独立硬链接只解除已选媒体库路径，不改写内容；仅删除明确选中的旁车，保留共享及人工维护文件，不承诺能释放仍被源链接占用的空间。失败/中断显示“移除未完成”及已生效策略，保留真实资产状态，可重试或撤销排除。

获取提交和文件发布前再次核对排除、缺失处理状态及计划版本；已经发出的下载器请求无法撤回，先核对接收结果并显示在途任务。选择排除后阻止其后续自动入库，暂停/移除该下载器种子仍是独立操作，不以删除共享数据作为取消手段。

先筛选，再排序

先验证作品身份、季集覆盖和硬性规则，再按用户有序偏好比较分辨率、来源、编码、语言标签、免费与做种数。保留规则版本和决策快照，能解释“为何选这个”。下载前的语言、HDR 等标签可能来自标题，不能伪装成已检测到的媒体轨信息。

首版提供少量内置策略，例如“1080p 优先”“4K 优先”“仅免费”；允许编辑阈值与包含/排除词。复杂表达式、原 MoviePilot 的 Python 正则规则和自动质量升级不直接迁移。

下载提交不重复

  1. 在短事务里创建下载意图并占用目标电影/剧集集合。数据库唯一约束裁决并发，防止手动搜索与订阅同时命中。
  2. 事务提交后解析下载材料，核对促销和文件范围，向选定的 qBittorrent / Transmission 实例提交任务；记录稳定种子身份及本地所有权，分类/标签仅按实际能力辅助标记。
  3. 请求成功则关联下载器任务；网络超时则标记“提交结果待核对”，按目标实例和 torrent 身份查询，标签可用时作辅助；确认不存在后才重试。结果不明期间不切换另一下载器重投。
  4. 按所选文件清单跟踪完成情况。核对下载器状态、文件大小、可读路径和搬移/校验状态后才能进入整理。
  5. 文件已入库后更新本地资产及订阅状态；刮削与飞牛扫描是独立任务，失败不能导致重新下载。

去重分三层：站点资源 ID、跨站 torrent 标识、内容对应的电影/剧集集合。BT v1/v2/hybrid 的身份由适配层统一处理，不能假设任何种子都只有固定长度的一种 hash。

上述内容占位用于 acquire（获取文件）。P1 辅种 cross_seed 和迁移 migrate 引用已有文件，不占用第二份获取名额；仍按操作目的、目标实例与种子身份幂等去重。发现同一内容并不代表能跳过文件校验，也不意味着可以复制一份新下载。

获取种子失败、促销过期或取消时，若确认尚未向下载器提交，意图进入 failed/cancelled 并在事务中释放占位；若提交结果不明，保留占位直到核对完成。已入库内容由资产记录承担去重，完成的下载占位及时结束，避免永久阻塞。

整季包的保守策略

  • 完整缺季且没有在途占位，文件清单能验证覆盖时，可自动获取整季包。标题中的 Complete 或 S01 本身不足以证明完整。
  • 如果已有 1–6 集，而包包含 1–12 集：首版默认进入人工确认。只有能可靠映射文件并验证下载器支持选择文件时，才启用“仅下载缺集”；复杂重叠包自动选择可作为后续增强。
  • 整包覆盖 E/H 中的排除或待处理集时，不能以“补齐整季”为由自动整包获取；只有可靠选定全部符合获取条件的文件才可自动继续，否则等待处理。手动确认整包也必须明确处理排除范围，不由普通确认按钮隐式解除。
  • 多集同文件保存一对多映射，不伪装成能无损拆成多个视频；跨季、绝对集号和特殊篇的歧义必须人工确认。
  • 以选定媒体文件清单为完成基准。整包只有部分文件完成时不标记全任务已整理，也不丢掉尚未完成的文件。

qBittorrent 与 Transmission 都通过官方接口接入；先探测实际版本与能力，再选择相应调用和状态映射，不为本项目强制升级既有下载器。qBittorrent 官方 WebAPI 文档；Transmission 当前 RPC 规范。两者具体差异与兼容范围见第 14 节。

08 · 识别、整理与飞牛影视入库

文件身份与安全整理

识别优先顺序：下载意图绑定的作品与季集 → 可信 NFO/显式外部 ID → 文件名与目录 → 元数据搜索。采用“确定、需核对、无法识别”三级结果，保存依据与冲突；没有校准数据时不用虚假的百分比置信度。

步骤要求
建立计划对每个源文件保存目标路径、对应作品/集、整理方式、源文件信息和冲突判断；执行前可预览。
路径校验拒绝越出授权根目录的相对路径/符号链接逃逸，清理非法文件名，核对下载器路径与应用路径；目录第一条识别结果不能套用整个混合目录。
硬链接默认保持源文件做种。初始化用实际临时文件测试 link，遇 EXDEV/权限错误明确失败；相同路径前缀或相同盘名不代表可链接。
复制用户显式选择；先检查可用空间及并发预留，流式写目标目录内临时文件；校验大小/流式校验值、同步后原子发布。
冲突目标已是本次已完成资产则幂等跳过；不同文件同名则暂停。不能仅以同名同大小判定同内容，不静默覆盖既有视频。
发布与恢复视频使用不覆盖既有文件的发布操作；旁车文件单独写临时文件，只自动更新本程序管理且未被人工修改的文件。外部或手工修改的 NFO/图片默认保留或提示冲突；作品级共享旁车串行更新。崩溃恢复对照计划、文件身份和数据库补记，不把 .partial 当媒体。
字幕与图片匹配已有字幕、保持语言/forced 标签；NFO/图片作为独立旁车。硬链接后的媒体内容不能原地修改，以免同时改变做种源文件。

飞牛适配是首版完整链路的一部分

建立专门 library/fnos 模块。配置飞牛服务地址、可选反向代理路径、影视账号及目标库；优先 NAS 局域网连接。首轮检测版本、认证、可见库和根目录映射，再开启库核对与刷新功能。飞牛影视账号与 NAS 账号并非同一账户体系，不能假定 NAS 管理凭据必然适合所有影视接口。

层次实现与结果
文件兼容应用将规范目录、NFO、海报写入飞牛已授权的媒体目录；飞牛设置启用优先读取本地 NFO/图片及实时监控。
原生连接实现连接/版本检测、库列表、媒体查找；根据实际版本支持刷新请求或等待实时监控，接口结果单独记录。
结果核对用来源 ID、作品类型、季集和路径映射核对飞牛条目；查询返回可见后才显示“飞牛已入库”。
兼容降级接口失效时保留本地整理与刮削成果，显示“文件已入库，飞牛同步待确认”；提供进入飞牛手动扫描的指引，后续恢复再核对。
不复制的能力不在新程序里实现播放器、转码或飞牛完整管理界面。

飞牛官方说明确认支持本地 NFO/图片优先及文件更新监控，并要求目录授权：飞牛影视安装与媒体库设置、飞牛影视目录授权说明。主动刷新、认证与条目查询的具体协议参考 MoviePilot 飞牛适配实现、MoviePilot 飞牛协议实现，属于需要对用户实际版本联调的兼容层，不是已确认稳定的官方开放 API；也不能因存在 Jellyfin 客户端兼容功能，就假定全部 Jellyfin 管理接口可用。

  • 启动时核对未完成下载意图、过期租约、临时文件与已发布资产；后台增量对账兜底，初次已有库扫描可以暂停/恢复。
  • 每次扫描记录根目录、挂载身份及完成度。根目录未挂载、无权限或扫描中断时保留原资产和去重事实；仅完整成功扫描的范围中，未见文件才标记待核对，再经挂载正常下的复查确认缺失。不能一次扫描遗漏就触发补下载。

全局暂停自动化（P0）

全局状态为 running → pausing → paused，显式恢复后回到 running。收到暂停请求先持久化控制版本并关闭自动操作的调度/提交入口；单副本执行器在领取任务及发出外部请求/发布文件前通过同一控制入口核对。已获准发出的操作可能仍在收尾，因此不能在点击后立即假报所有工作已停止。

对象暂停期间的行为
新自动工作不启动新的订阅搜索、站点增量拉取、下载提交、整理、刮削写入及飞牛刷新；P1 自动插件也经过同一控制入口。待执行任务进入 waiting_paused，不消耗失败重试次数，不释放有效下载占位。
执行中工作搜索响应可收尾但不继续自动下载；复制在可恢复分块处停下并保留可追踪临时文件；已经完成的原子文件操作补记状态后停止后续步骤。已发下载器/飞牛请求先核对结果，超时结果不明则显示待核对，保持正在暂停。
仍可使用浏览、日志、配置、手动搜索/识别预览、有限的只读状态核对继续可用。手动搜索受站点限额约束且不连带自动下载；手动提交下载、整理、刮削、移除文件或执行插件需先恢复。对既有种子的明确暂停/继续操作独立处理并记日志。
已有下载与做种下载器继续按自身设置运行，全局开关不批量暂停或删除它们。下载完成可同步记录状态，后续自动整理等待恢复；用户维护 NAS 时可另行暂停下载器。
重启与恢复暂停控制与任务状态持久化；pausing 重启后继续核对，paused 重启后仍暂停。恢复前重新检查配置、映射、排除、文件和配额；同一订阅合并必要补查，限流分批执行，不重放每个错过的检查时刻。
P1 交接中的插件不在暂停源/启动目标之间直接杀死执行单元；按已记录的交接阶段完成必要收尾或恢复源状态，再进入暂停。界面显示正在收尾的操作，全局开关不承诺瞬间冻结外部下载器。

waiting_paused 是可恢复的调度等待，不是失败或取消。全局恢复不能隐式恢复单独暂停的订阅，也不能解除用户的内容排除。备份恢复后默认保持自动化暂停，先核对下载器、媒体文件及恢复时间点之后的差异，再显式启用；恢复快照不是回滚外部文件或下载器状态。

10 · 日志系统与问题排查（P0）

日志系统是首版基础设施。用户需要看懂“为什么没有下载、哪一步失败、能否重试”；开发者需要关联请求、任务和外部接口，定位代码与协议问题。两种用途共用关联 ID，提供不同详略的视图。

独立入口：日志中心。任务详情提供“查看相关日志”和“执行时间线”。失败卡片先展示简明原因、最后成功步骤、下一步建议和重试时间，再展开技术细节；错误不能只存在于容器终端中。

任务事件一次手动/订阅流程中各步骤开始/完成/失败、候选统计、拒绝原因、选中资源、重试与人工纠错。SQLite job_events，关键状态变更与业务状态同事务提交；形成用户可读时间线。崩溃恢复依赖业务状态，而非解析日志文本。
操作记录谁在何时修改订阅/策略/集号映射、移除文件、设置或解除排除、手动整理、暂停/恢复全局自动化、暂停/重试任务、变更连接设置、开启 DEBUG 或导出诊断。SQLite audit；只保存非敏感摘要，不保存密码旧值/新值。记录计划版本、影响范围、完成与失败结果。
前端错误页面运行异常、接口错误码、页面版本与后端 request_id；用户点击失败时能定位。限流写入运行日志；只接收允许字段、限制体积。生产堆栈映射按构建版本在开发排查中使用，不上传表单值、Cookie 或整个浏览器状态。

10.2 全流程关联与统一字段

一次订阅检查或手动操作生成 workflow_id，贯穿搜索、筛选、下载、整理、刮削和飞牛同步。每个后台步骤有 job_id，重试沿用 job_id 并增加 attempt；子任务记录 parent_job_id。HTTP 请求使用 request_id，返回响应头/错误体；入队时把关联信息持久化，不能只留在内存 context 中。

公共字段：时间（UTC RFC3339，界面按用户时区显示）、level、module、event、message、app_version、instance_id、workflow_id、job_id、request_id。适用时添加 site_id、media_id、download_id、import_id、attempt、duration_ms、error_code、retryable 与 next_retry_at。不得为了凑齐字段填假值。

{
  "time": "2026-10-14T14:00:00Z",
  "level": "WARN",
  "module": "sites.mteam",
  "event": "site.rate_limited",
  "message": "站点请求受限，已安排重试",
  "workflow_id": "wf_example",
  "job_id": "job_example",
  "attempt": 2,
  "duration_ms": 850,
  "error_code": "SITE_RATE_LIMITED",

10.4 日志中心与开发调试

  • 日志中心支持时间范围、DEBUG/INFO/WARN/ERROR、模块、站点、任务/流程 ID 和关键词筛选；实时跟随、暂停滚动、复制单条、分页历史、按当前筛选导出。显示当前日志最早时间与保留范围。
  • 从订阅/下载/手动整理任务跳入关联时间线，再展开单步技术日志。用户不必自己在整份文本中寻找 hash 或猜发生时间。
  • 开发环境默认 DEBUG，可用便于阅读的终端格式；生产默认 INFO，结构化落盘。DEBUG 是增加解析/调用细节，任何级别都不能关闭凭据脱敏。
  • 支持对单个模块/站点临时开启 DEBUG，默认 30 分钟自动恢复；界面展示范围和剩余时间，进程重启清除临时覆盖，避免长期误开。级别切换不要求重启。
  • 进度轮询只记录状态变化和定期摘要，不每秒打印百分比；健康检查和正常心跳不刷 INFO。同类网络错误合并时保留首末时间、次数与被抑制计数。
  • 未知错误/可恢复 panic 记录堆栈和关联任务；正常业务拒绝使用原因码。panic 后不能把任务标为成功；不可恢复进程故障由重启与状态对账处理。

以 Go log/slog 统一结构化输出、字段和级别；日志封装只处理上下文、脱敏和输出策略。轮转、有界队列、实时订阅和文件查询由应用层实现，不能误认为 slog 自动提供这些功能。Go slog 官方文档

项目初始设计值边界
运行日志保留7 天或 200 MiB 总量，先达到者触发清理；单文件 20 MiB。可配置；按时间/序号轮转，统计当前文件在内。界面说明实际可查询范围，不保证在高流量下仍有完整 7 天。
任务事件/操作记录已结束任务的详细事件 90 天，操作记录 180 天。定期分批清理并保留业务最终状态；未结束/待人工处理任务所需事件保留。设置容量告警，不能把核心恢复状态一起删除。
内存与输出共享日志缓存、队列和实时订阅缓冲初始总预算 4 MiB，单条编码后上限 16 KiB。条目超限截断并标记。异步写入、批量刷新；正常退出尝试限时排空，断电/强制终止不承诺尾部运行日志零丢失。
拥塞或磁盘写失败优先丢弃/聚合低级别重复日志，预留 WARN/ERROR 容量，公开丢弃数和写失败状态。重要事件优先写入，但持久介质不可用时不保证运行日志完整；业务关键事件随事务保存，业务数据库也不可写时必须暂停相关写操作，不假报成功。
历史查询默认最近 15 分钟、每页 100 条，最多 500 条。按轮转文件时间范围流式检索；单次扫描上限初始 32 MiB 或 2 秒，未扫描完返回 continuation cursor 与“尚未查完”，支持继续扫描，不能把局部无命中当全部无结果。
实时与导出SSE 每个客户端有界缓冲；慢客户端断开并返回缺口提示；导出按选择范围流式生成。界面仅保留最近 2000 行，历史按需加载；运行日志超出保留范围无法补回，持久任务时间线仍可单独查询。
Docker 输出显式设置容器日志驱动与轮转，另计磁盘预算。应用文件与 Docker stdout 是两个存储位置；不能只限制应用文件而放任容器日志无限增长。

应用日志文件位于本地配置盘，网页通过受认证的后端接口访问。运行日志无需全文索引服务，关键任务事件用数据库索引查询即可；日志保留、DEBUG、查询和故障注入均计入现有内存/I/O 基准。Docker 轮转行为按所选驱动配置并验证，参见 Docker 日志驱动与轮转说明。

10.6 脱敏与诊断导出

采用允许字段列表，在进入任何输出目标前脱敏。禁止记录密码、Cookie、Authorization、API Token、authx、访问码、passkey、带凭据下载链接或整份原始 HTTP 请求/响应；异常字符串与嵌套字段同样处理。站点响应仅保留状态码、内容类型、长度、耗时及允许的错误码；确需模板样本时单独手工脱敏，不把它混进普通 DEBUG。

诊断包由用户主动生成和下载，包含所选时间/任务的脱敏日志、任务摘要、应用/协议版本及非敏感配置。导出前可预览，默认用稳定占位符替换私有域名/IP和绝对路径，不包含凭据库、完整数据库或种子文件；导出不自动上传。日志查看、级别修改和导出都需管理员认证；网页以文本渲染外部错误，防止日志内容被执行。

10.7 日志系统验收

  • 给定一个失败任务，能从页面找到触发者、各步骤、最后成功点、明确错误和下一次重试；并发任务与重启后的重试不会串线。
  • 分别模拟五站认证过期/限流、qBittorrent / Transmission 响应超时、目录权限不足、NFO 失败和飞牛扫描错误，普通用户能在任务详情定位原因，开发者能找到相同关联 ID 的技术记录。
  • 在 Cookie、请求 URL、异常文本、嵌套 JSON 和前端错误中注入测试秘密，网页、文件、stdout 与诊断包均不能出现原值。
  • 日志轮转期间查询、实时订阅及导出均能正确说明游标连续性/缺口；达到扫描预算显示尚未查完，不能显示误导性的空结果。
  • 制造日志洪峰、写权限错误、慢客户端和磁盘配额不足：缓冲有界，日志故障可见，业务失败状态不丢失且不被错误标记成功；不可写的业务数据库停止相关操作。
  • 临时 DEBUG 到期/重启自动恢复；正常退出刷新日志；强制终止后关键业务状态可恢复，并承认运行日志尾部可能缺失。

13 · 实施顺序与验收门槛

按可验证的纵向闭环实施。五个站点都在首版范围内，但每个阶段可以只用一个站点和一个受控样本验证流程，最后再达到完整交付范围。

M1 · 手动闭环发现/详情/演员/相关推荐；一个站点搜索与 qBittorrent；独立手动整理入口与按剧集号映射；预览、整理、刮削、飞牛可见；日志中心和任务时间线。电影、普通剧与常看国漫三个样本端到端成功；本地文件可不经下载直接整理；断线不重复下载，失败任务能在日志中心定位。

M3 · 恢复与既有库已有库扫描、主动移除/外部缺失处理、人工纠错、故障恢复、备份/恢复、飞牛同步对账、错误中心；日志轮转/洪峰/脱敏导出验收。正确性与日志验收均通过；故障/移除不会触发意外补下载；原始做种文件和已有库没有被误改/误删；恢复后先暂停核对，日志可见且资源有界。
M4 · P0 NAS 验收真实 NAS、双下载器版本矩阵、72 小时稳定性报告、部署文档、扩展接口和事件契约测试。五站、qBittorrent、Transmission 和飞牛均有实测；无插件进程时核心独立运行，资源目标达标或明确修订。
M5 · P1 插件运行与管理插件包/清单、版本化协议、配置与范围、按需执行、事件重试、日志与任务管理；提供示例插件/SDK。插件崩溃、超时、重复事件和升级不破坏核心；禁用后不接新任务；无插件启用时不常驻子进程。

工作量判断：难点主要在站点差异、命名识别、文件恢复和飞牛版本兼容，页面不是主要不确定性。适合先完成 M0 再估排期；本稿不虚报固定天数。开发时优先写命名解析、筛选、去重、状态机和协议适配的有效测试，不为每个 CRUD 页面堆重复测试。

开工与交付边界：以本稿 P0 为基线，先完成真实路径、接口和三个代表样本验证，再扩展页面及全量适配。路径测试记录下载器/应用/飞牛三方所见目录、文件系统与子卷，实际验证硬链接；不原地改写共享媒体内容。资源报告同时给出主进程与整个必要部署组合的口径，所有内存数字仍须实测。升级前做一致备份，恢复演练覆盖数据库、配置、密钥及外部状态核对；旧二进制不直接打开不兼容的新 schema，失败时停止自动化并按匹配版本与备份恢复。

14 · 双下载器与 P1 插件扩展设计

P0 将 qBittorrent 和 Transmission 作为同等支持的下载器，统一入口、分开适配；P1 交付可管理的插件运行机制及辅种、转移做种插件。现阶段先把身份、文件引用和副作用执行边界设计好。

不新增独立的“做种任务”模块。下载完成后，原种子继续由 qBittorrent / Transmission 做种；应用只同步其状态、保留文件关联。P0 不增加做种菜单、不为每个种子创建常驻后台任务。P1 插件负责加种、校验和交接等有明确结束条件的操作，完成后仍由下载器持续做种。
术语含义与界面位置
下载器种子记录对应某个下载器实例中的一个 torrent，状态可能是下载、校验、暂停、做种或排队；统一在下载管理中展示，不因下载转为做种而新增一条记录。
文件关联记录说明某个种子使用哪些源文件，以及这些文件与媒体库资产的关系。用于整理和后续辅种/迁移时避免误改文件，不是用户需要管理的任务。
应用后台任务一次搜索、整理或 P1 插件操作，有开始、结果和日志。辅种操作完成后即可结束，不随下载器持续做种而永久保持运行。

14.2 P0 必须保留的资料与事件

  • 从站点取得 .torrent 时保存受保护的原始材料引用与稳定标识，避免 P1 才发现客户端无法导出种子。文件可能包含 passkey/私有 tracker 信息，按凭据等级保护，不进入普通日志和诊断包。
  • 磁力任务取得完整元信息后，只有客户端/API 提供可验证材料时才能归档；拿不到则标记 metainfo_unavailable。后续迁移可要求用户补充种子，不能凭 infohash 或文件名伪造完整 .torrent。已有任务接管也要显示材料是否齐全。
  • 以应用自己的稳定资产 ID 记录来源文件、整理后文件及各客户端引用。文件名、大小、infohash 分别表达不同事实；两个站点的种子 hash 不同，也可能引用同一内容，反之同名同大小不能证明内容相同。
  • P0 为已管理任务保存基础文件使用关系、创建来源和操作目的；P1 从这些数据扩展辅种/迁移关系。引用记录需对账，不能用“引用数为零”单独证明文件可以安全删除。
  • 复用持久任务事件，定义小型事件封套：event_id、schema_version、event_type、occurred_at、workflow_id、job_id、subject_id 和因果来源。候选事件包括 download.completed、import.completed、scrape.completed、library.visible、job.failed；P0 不运行插件消费者。
  • 事件在状态成功提交后才可见；P1 增加消费游标、重试/失败队列。至少一次投递，插件与宿主命令都按 event_id / operation_key 幂等；插件来源事件标记 causation，防止自己的加种完成事件无限触发自身。

PL-04日志和恢复统一 workflow_id/job_id/plugin_id/plugin_version；插件 stdout 为协议，stderr 结构化日志经宿主脱敏。异常、超时、事件积压可见，插件崩溃不将核心任务标成功。
PL-05受控宿主接口查询授权资产/种子、搜索获准站点、提交辅种/迁移计划、申请校验和任务操作；不直接读写核心数据库，不拿完整站点/下载器凭据，不提供任意文件删除/RPC 透传。
PL-06版本与资源执行前做协议握手，拒绝不兼容包；记录运行时插件版本，升级后旧任务不得无条件换实现续跑。默认按需启动、有限并发、空闲退出，配置执行超时与输出上限。

建议运行方式：宿主启动编译后的 Go/Rust 插件子进程，通过有大小上限的版本化 JSON-RPC（stdio）交互；核心和官方插件不依赖 Python。起步只支持本地、明确安装的可信插件，默认一次一个插件执行单元，长流程每步状态由宿主持久化，避免每个插件常驻一个服务。首版核心依然是单进程，P1 启用插件时才计入额外子进程成本。

Go 原生动态 plugin 包存在平台、工具链与依赖匹配等约束，本稿采用进程协议降低耦合。子进程隔离主要用于故障隔离，本身不是安全沙箱；若未来开放不可信第三方插件，还需受限 OS 身份/容器、文件与网络隔离，不能只靠 manifest 声称已经隔离。Go plugin 包的限制说明

完整插件 SDK、安装界面、消费者与管理表在 P1 实现；P0 只完成接口契约、事件字段和确实需要保存的来源数据。插件无需承诺兼容 MoviePilot 的 Python 插件，后续功能通过新宿主 API 重新实现。

14.4 P1 辅种插件

  1. 选定已完成、可读且允许使用的文件资产，搜索获准站点或导入候选种子，生成匹配预览。文件数量/路径/大小用于初筛，不能作为内容一致的最终证明。
  2. 按候选种子的原始文件布局建立引用计划；同盘可建立独立硬链接视图，跨盘复制需用户明确选定并计算空间。不重命名或修改现有做种文件。
  3. 在目标下载器以停止/暂停状态添加候选，绑定对应文件目录，并执行完整校验；根据客户端真实状态核实校验完成和所需数据完整。
  4. 只有校验通过才启动做种。校验不通过保持停止并报告差异，默认不允许下载器补下载缺失块，以免写坏共享文件或制造未预期流量。
  5. 保存目标种子、目标实例、文件引用和校验结果；重复事件不重复加种。辅种不新增一份媒体资产，不重新刮削或重复触发订阅获取。

14.5 P1 转移做种插件

首个版本针对同一 NAS 或两端已能访问同一份完整文件的 qBittorrent ↔ Transmission 交接，两个方向分别验收。异机数据传输和复杂存储搬迁留待另行设计；“转移做种”不自动等同于“移动文件”。

  1. 生成计划：源/目标实例、原种子材料、目标目录映射、选中文件、当前校验状态和交接后源任务处理方式。首版只迁移已完整的种子；缺元信息、文件缺失或能力不足时停在准备阶段。
  2. 目标先以停止状态添加，映射到原始数据布局并校验；使用原种子材料，不导入另一客户端下载缓存来假装已校验。源任务此时保留。
  3. 目标校验完整后进入交接：暂停源任务并确认，再启动目标任务。记录目标进入可做种/排队做种状态；没有 peer 不应误判失败，也不声称已经发生上传。
  4. 目标启动失败时按记录恢复源任务原状态；网络结果不明先核对两端，不能盲目同时恢复/重投。所有阶段持久化，重启后对账再继续。
  5. 默认保留源任务（暂停）与源文件，提供结果核对和恢复入口。若后续需要移除源任务，只能走明确的“保留数据移除任务”操作；P1 不默认删除共享数据。

共享文件仍被任一种子使用时，整理/迁移应获取相应操作锁并尊重引用状态。实际移盘必须是独立计划，先验证所有使用方的路径和恢复策略，不让插件直接对下载器调用带搬移副作用的接口。

14.6 P1 交付验收

场景必须结果
同一文件用于多个种子/两个下载器可表达多重引用；订阅仍只认一份已入库资产；合法辅种不被 acquire 防重机制拦截。
同名同大小但内容不同候选可初筛通过，但实际校验失败；目标不启动补下载，源文件不被改写。
Transmission 重启或 RPC 协议差异按稳定身份重新关联；不同协议适配有明确测试范围，不因数值 ID 复用操作错种子。
源客户端不能导出种子优先使用受保护材料库；缺材料时报告不可迁移，不伪造元信息或假报成功。
目标校验失败 / 启动失败 / 进程重启交接前不停止源；交接失败按原状态恢复；重启核对阶段后续做，不重复加种。
重复事件 / 插件递归触发同一个操作只产生一个有效计划，记录幂等和因果来源，不形成无限加种循环。
插件越范围请求或已接管外任务不足宿主拒绝操作且日志可见；不扩大到所有下载器任务或其他目录。
插件超时、崩溃、禁用、升级核心仍可运行；任务可恢复/安全终止；升级校验接口和状态版本，禁用后不接受新触发。
未启用插件 / 高负载插件没有常驻插件进程；启用后记录整个进程树 RSS/CPU/I/O，单独给出 P1 总资源验收，不能拿 P0 主进程内存冒充全部占用。
