# v0.3.20 飞牛影视 NAS 根地址兼容

用户要求与原版 MoviePilot 一样，只填写 `http://192.168.8.129:5666` 或 `https://192.168.8.129:5667` 即可连接，不需要手工追加 `/v` 或改用 8005。

修复前在部署实例复现：当前地址为 HTTP 5666，连接测试第一步返回 `HTTP_302`、`authenticated=false`、请求数 1。无凭据网络检查确认 5666 的版本接口跳到同 IP 的 HTTPS 5667；5667 使用 NAS 自签证书，正常证书校验失败。原版 `app/modules/trimemedia/api.py` 使用 `RequestUtils`，后者在 `app/utils/http.py` 默认 `verify=False` 并沿用会话重定向，因此旧实现不能算对齐原版。

本版变更：

- 配置继续接受根地址、`/v`、`/v/`，内部统一为 `/v`。
- 仅为配置的私网／回环 IP 或 localhost 飞牛连接克隆独立 TLS transport，兼容本地 NAS 自签证书。公网 HTTPS 与其他服务保持正常证书校验，不改全局 transport。
- HTTP 入口通过无账号密码的签名版本请求确认同主机 HTTPS 5667 升级，再向确认后的影视入口发送登录 POST。登录及后续 API 不跟随重定向，避免 302 改变登录方法及凭据被转发。保留请求数、超时和响应体边界。
- 同一字面量私网 IP 的默认入口 `http:8005`、`http:5666`、`https:5667` 可切换并保留已存密码；换主机、任意端口或账号仍需重新提供密码。
- 设置地址示例改为 NAS 5666 根入口。

本报告取代 [v0.3.17 的连接限制](fnos-connection-v0.3.17.md)；旧报告描述的是当时仅支持 8005 HTTP、拒绝全部重定向和自签证书的状态。

发布前使用新连接器完成 NAS 实机只读验证：两个根入口均 `status=passed`、`authenticated=true`，HTTP 5666 为 12 次请求，HTTPS 5667 为 11 次请求；前端版本 0.9.8、后端 0.8.43。两者另用实际 `Service.Libraries` 分别读到 7 个媒体库。没有执行扫描、重新刮削或媒体文件修改。

合成验证使用真实 `httptest` HTTP 302 与自签 TLS 服务，逻辑 5666/5667 通过测试 transport 映射到独占随机端口。检查版本探测无凭据、每跳签名、登录保持 POST、实际鉴权读库，以及跨主机、HTTPS 降级、未配置端口、登录重定向和 URL 改写被拒绝。独立审查修正了最初同 IP 任意 HTTPS 端口过宽的问题；最终只允许配置 origin 或已确认的同主机 HTTPS 5667 升级。另覆盖 20 请求总额、3 跳和整条版本解析链共用 12 秒期限、TLS 配置克隆隔离；针对性 race 检查通过。这些均为合成协议测试，与 NAS 实机结果分开计证。
