# Light Media v0.2：操作对照与验收

日期：2026-10-15。项目独立于原 MoviePilot，Go 后端与 Vue 网页界面，无 Python 运行依赖。

先纠正之前的交付判断：v0.1 虽然跑通了部分核心链路，却缺少站点和下载器的独立管理、文件浏览与整理历史等主要入口。我此前直接说“全部完成，可以使用”，判断过早。此次按你指出的操作差异重新核对原版组件、后端行为和实际页面，不再把接口存在或测试通过等同于完整使用体验。

## 手动整理怎么用

1. 在“文件管理”进入源目录，选择文件或目录，点击“识别 / 手动整理”。源路径来自所选项目，无需手填绝对路径。
2. 同一部剧选择“同一影视”；不同电影或影视混放时选择“逐项识别”，逐文件搜索并明确选择身份，也可明确采用 NFO 身份。
3. 选择目标库和硬链接/复制方式。剧集可统一季号、按原始集号加偏移，或按文件名自然顺序从起始集连续填写；应用后仍可逐文件修改。高级映射在折叠区域，预览会核对官方季集。
4. 查看逐项源路径、目标路径、方式、空间预估和冲突，再确认。不同影视分别创建计划，批量操作保留各项结果；已成功提交的项目不会因重试而重复提交。
5. 在“媒体整理”查看整理结果与任务链。成功文件的媒体资产可继续查看刮削及入库状态。

已登记媒体可从文件管理选择文件或目录后单独刮削。文件管理不盲目改写已有媒体库；已有资产的删除与维护走媒体库的资产管理流程。

## 版本核对

本次新增操作已在独立测试实例中按上述流程实际验证；构建、完整回归及最终 NAS 程序标识以同次交付的 BUILD.txt、SHA256SUMS 和发布验收单为准。原始 v0.1 的下载器实传、飞牛临时库验证与备份恢复记录保留在源码 docs/p0-acceptance.md，不将它们冒充为本次新增界面的同一次运行。

自动订阅支持经过实际种子文件核验的明确同季资源包：只冻结实际覆盖的已播缺集。含起始集之前、已有、跨季、未播或未知文件的包保留人工核对，提交前再次核查元数据。

## 仍然明确保留的边界

- 本版对齐上述常用操作，不宣称 MoviePilot v2 全量功能或每个细节完全 1:1。
- 站点原生适配仍限确认的五站；下载器限 qBittorrent 和 Transmission。任意站点、其他下载器、CookieCloud、破解浏览器验证等没有伪装成已支持。
- 当前整理采用规范化命名、保留源的硬链接/复制，没有提供无实际实现的“不重命名”开关。单文件多集合并、特别篇季 0、自定义剧集组、任意集号正则、AI 整理、已有资产目标改认及原版所有高级批处理尚未复制。
- 多部影视允许逐项明确身份后批量确认，不根据模糊文件名自动认领身份并执行。
- 文件删除采用同目录隐藏回收区，并支持快照核对后的恢复；它保留数据，不等同于永久擦除。媒体库、下载器现有任务保存目录及被引用文件受到保护，未知或无法核验时会拒绝破坏性动作。
- 云盘按已确认需求不包含。P1 插件、辅种、转移做种尚未实现。
- 本轮没有完成 72 小时连续稳定性测试；局部实机成功不能代替长期稳定性结论。
