## 0.58.29 的变化

- 网页在服务器核对媒体身份与季集、提交订阅事务后显示成功。同一个事务持久化新增通知的待执行状态，后台沿用已有流程发送通知、发布新增事件和处理统计。保存失败仍返回错误，重复提交保留同一订阅 ID。
- 新增事件优先读取实际写入的事件表，老数据仍可从旧表验证。统计配置从迁移程序实际写入的位置读取。已有客户端可以继续等待整个流程完成。
- 从作品页打开表单会复用已选作品和确认过的季度列表。影视卡片需要判断订阅状态时只查当前作品，不再下载整页订阅进度。旧生产接口在本次三次读取中每次返回 107,855 字节。

## NAS 隔离实例的浏览器实测

使用局域网 Chromium、NAS 机械盘上的独占临时数据目录，以及与生产相同的 Go 内存设置。电影和电视剧分别复用了生产 NAS 缓存的对应 TMDB 原始元数据。页面上的初始作品卡片、通知收件端和季集样本是测试夹具。浏览器通过正常网页提交，后端实际保存订阅。每笔操作随后核对了新增事件、一次通知和后台任务完成状态。没有对生产订阅执行新增或取消。

| 作品 | 从点击添加到表单可见 | 从点击保存到收到有效订阅 ID | 从点击保存到页面提示成功 |
| --- | ---: | ---: | ---: |
| 电影样本 | 157 毫秒 | 758 毫秒 | **761 毫秒** |
| 电视剧季度样本 | 149 毫秒 | 266 毫秒 | **270 毫秒** |

另用较小的合成元数据分别走三次正式 HTTP 保存入口，电影为 149、142、181 毫秒，电视剧为 127、214、164 毫秒。上述时间不含首次向外部媒体源获取未缓存资料的耗时。隔离实例没有生产调度负载。

## 部署后的生产核验

0.58.29 实际进程与 eMMC 上的发布文件 SHA-256 一致，容器内存软阈值为 169,996,288 字节，18 个插件载入，自动调度运行。核验时生产数据库位于原机械盘。

生产浏览器打开样本电影的订阅表单用了 **157 毫秒**，打开样本剧集的季度选择用了 **125 毫秒**，均在对应作品详情已经显示后开始计时。生产库中该电影有且只有一条有效订阅。本次对生产的订阅接口只做读取。

只查当前作品的接口返回 165 字节（电影）及 161 字节（电视剧）。刚部署后三次电影请求分别为 914、14、11 毫秒，电视剧为 33、11、8 毫秒。单次复测不能覆盖不同外站和后台负载。

## 验证范围

浏览器构建和 639 项前端测试通过。Go 定向回归覆盖电影、电视剧、重复提交、无效请求、事务回滚、兼容调用等待统计、冷启动恢复及无效签名。生产写入未重放。另跑的首次检查排程回归中，五项固定间隔断言与原有随机排程不一致，本次没有修改排程。Linux 测试二进制通过临时 Go overlay 排除另一份历史测试文件的未使用导入。
