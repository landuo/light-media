# 插件日志：原版操作、Go 实现与证据边界

对应平台清单 PL-30。入口是「我的插件 → 插件操作 → 查看日志」，保留另一个「执行记录」入口；执行结果元数据与连续日志不能互相替代。实现面向已安装的具体实例，后续分身也不能混读基础插件的日志。

## 原版依据

只读核对 MoviePilot-Frontend 的 `src/components/dialog/PluginLogDialog.vue`、`src/views/system/LoggingView.vue`、中文语言文件，以及 MoviePilot 的 `app/api/endpoints/system.py` 日志接口。日志视图源文件 SHA-256 为 `e5b6b5434d823c16c02d57c4524b5c5e261fb88b5c5aeff5bf44797d5bf1597f`。离线抽取原函数生成的参考保存在 `testdata/plugins/logging-original-oracle.json`，不执行用户插件或读取配置。

操作沿用 72rem 弹窗、窄屏全屏、下载和新窗口入口、全部/指定级别与关键词过滤、暂停/恢复日志流、靠近底部跟随、上滚后新日志计数及「查看最新」。初始最近 50 条、显示最多 600 条、80ms 批次刷新、相同秒与级别且相邻间隔不超过 100ms 的分组、32px 跟随阈值、300ms 首次连接、3 秒重连和最多 3 次重试、后台 5 秒断流均与该源版本对应。原函数还允许倒序时间差和缺失时间值，参考没有把这些边界改成自行定义的排序规则。

## 实现

前端为 `PluginLogDialog.vue`、`features/plugin-logs.ts`，按需加载。Go 结构化记录先适配成原视图需要的字段，使用 Vue 文本插值；不执行日志中的 HTML。WARN/FATAL 显示为 WARNING/CRITICAL。时间保留毫秒，0 时间戳不丢失。具体实例、稳定记录 ID、单条长度均检查；缓冲与最终列表都有限额，稳定 ID 去重覆盖历史/实时边界和重连。

后端为 `internal/app/plugin_logs.go`，使用现有日志的脱敏、轮转、查询游标和 SSE。四个 GET 入口均经现有管理员认证，兼容根路径及 `/light-media` 反向代理前缀：

| 路径（接在 `/api/plugins/{instance_id}` 后） | 行为 |
| --- | --- |
| `/logs` | 最近 50 条保留记录及在读盘之前捕获的 SSE 续传边界 |
| `/logs/stream` | 只推送该实例，支持恢复、心跳和缺口通知 |
| `/logs/file` | 全部现存保留日志，最新行在前，纯文本新窗口 |
| `/logs/download` | 全部现存保留日志的真实 ZIP，内部日志按时间从旧到新 |

查询的实例由宿主 URL 确定，不能传入文件名、其他实例或执行 ID 改变范围；不存在的实例拒绝读取。历史查询保留磁盘损坏/清理的缺口提示，同时返回捕获边界，避免缺口历史反复触发实时重连。SSE 继续使用全局最多 8 个流的限额。

导出先完整生成再发送响应头，不把部分内容假装成完整文件。通过固定查询快照和有界游标分页读取，单次导出最多 1 GiB，与设置中允许的最大日志保留量相应；超过时明确失败，不截断。临时文件权限 0600，打开即 unlink，只保留文件描述符；单并发导出、两分钟上下文与响应写入期限，取消或进程退出不遗留命名日志副本。日志读取发生清理或损坏时返回 409，客户端可重新下载。既往全局丢日志健康计数会提示缺口，但不阻止导出仍完好的保留记录。

## 格式与未完成边界

新服务日志由宿主统一脱敏并以 JSON 轮转存储，因此 ZIP 是按实例筛选后的文本投影，单个聚合 `.log` 位于 `{lower_id}-logs-时间/` 中；不是复制原 Python 日志的各个轮转文件，亦非逐字节相同的旧日志迁移。纯文本新窗口导出全部现存保留记录，而原 `length=-1` 接口只读取当前日志文件。旧日志尚未迁移，这些范围差异不能被称为原文件兼容完成。

只包含实际产生并保留的日志。尚未重写的插件不能因此被认为已经有业务日志，保留期已清理的记录无法恢复。此功能不增加已迁移插件数，也不替代 23 个插件的业务、配置/KV/文件迁移及正式切换验收。
