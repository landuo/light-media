站点消息开关迁移与运行时继承（2026-10-21）

开发代码新增独立的 Go 离线迁移工具 site-message-settings-migrate-owned，补齐原版 SITE_MESSAGE 与新项目“阅读站点消息”的衔接。它不属于 Python 兼容环境；产品仍全 Go。正式迁移数量保持 7/23，生产仍为 v0.4.8；本批未部署、未签发执行交接，也未向用户站点发送请求或标记真实消息。

原版依据
只读采集固定安装版本的 core/config.py 和 utils/system.py，只选 CONFIG_DIR 与 SITE_MESSAGE，通过 AST 保留相关字段和通用转换规则；未导入原 App、未调用原 Settings 构造函数或环境写入函数。14 份合成参考覆盖缺省、常见布尔文本、数字文本、无效值及来源优先级。参考明确显示原版缺省 true，无效文本也经原规则转为 true；本工具接收参考推导后的布尔结果，不在 Go 中猜测环境字符串的转换。

实际配置做了两次相等的冷推导，再分别用 Go 工具的 --validate-input 从 stdin 校验；读取时原配置内容与原容器身份均未变化。只确认当前配置文件推导值为 true，不代表原进程的内存缓存，也不代表站点认证、实际通知或完整插件迁移已完成。配置正文不落文件，不导入完整环境变量。

迁移约定
输入包含固定来源哈希、原 app.env 内容摘要、布尔值、来源模式和零副作用证明。校验拒绝重复/未知键、缺失/null、错误类型、错误来源或非零副作用。新增 source_site_message_settings 一条独立 AES-GCM 记录；关联既有 source_settings_migration 收据，并校验此前三个域的密文、结构及完整摘要。不同配置快照、残缺/损坏的父迁移、既有不同值均拒绝。

工具仅允许显式指定的已存在、已停止的独占目标，复用已有目标锁、模式版本及活跃任务检查。默认只读预检，--apply 才原子写入。重复导入相同内容返回 already_imported，写入数为零。不会创建实例、启动 worker、排队任务、重放单次执行或修改其他迁移域及原生用户设置。

运行行为
原生 read_site_messages 保持可空：没有来源记录时沿用原缺省；有经核验的来源记录且用户未手动选择时继承来源；用户明确 true/false 优先。公开 settings 保留原生可空值，另投影 effective_read_site_messages，页面显示实际生效值。保存 TMDB、飞牛等其他设置时不把继承值变成显式选择。损坏的来源记录显示明确错误，禁用该开关的保存；正式刷新在请求前拒绝，普通站点连接测试仍只测资料连接、不阅读消息。

正式刷新在每次账户/消息请求前和结果提交前重新核对消息策略及来源摘要。采集中撤销后不继续标记已读，也不发布这次账户快照、事件或成功收据。来源值更改或父迁移损坏不会被当作普通站点空结果。此次实际 SDK 测试最初把这两个预期失败分支误写成成功预期；已保留失败记录，改为检查失败码、零发布和精确请求序列。
