# 光影当前需求与交付范围

更新日期：2026-10-17。交付目标是可实际使用的独立影视自动化程序，核心流程为“选择影视 → 订阅或搜索 → 筛选资源 → 下载 → 识别整理 → 刮削入库”，并提供推荐榜单、演员资料和相关推荐。后端与迁移中的 23 个插件均使用 Go，前端使用 Vue 3 / TypeScript，运行时不依赖 Python。

操作及 UI 以原 MoviePilot v2 和实际安装插件为准，用户随后明确纠正的交互优先。早期方案和实现中与当前要求冲突的站点范围、下载路径、手动整理及插件范围，均按下列要求处理。完整插件平台及全部已安装插件的迁移已经纳入当前持续交付范围；当前实现进度见[迁移清单](plugin-installed-migration-baseline.md)，需求列入不等于实现完成。

## 发现与资源搜索

| 功能 | 必须具备的操作与结果 |
| --- | --- |
| 影视发现 | 榜单、热门/趋势/高分内容、作品详情；提供订阅和搜索资源入口。 |
| 演员与推荐 | 演员资料、相关作品和作品相关推荐；区分真实来源和缓存更新时间。 |
| 搜索 | 影视搜索混合显示电影与剧集；支持直接输入关键词搜索站点资源，不要求先确定 TMDB 身份。 |
| 结果与筛选 | 沿用原资源结果的展示、排序、过滤及下载操作；多站并行，先完成的站点先显示结果。 |
| 识别规则 | 全局/订阅局部识别词、优先级规则及质量/分辨率/特效条件进入实际识别和选择过程，不能只保存表单。 |

馒头、憨憨、UBits、家园、1PTBA 是必须支持的原生适配范围，同时允许其他站点复用通用 NexusPHP。站点添加必须具有对应搜索、种子获取和账户数据行为；暂不支持的协议或页面应返回可判断的失败。

## 站点与下载器

“站点管理”是添加、编辑及维护站点的唯一入口，提供原版卡片和菜单、排序、账户数据、单站/多站连接测试、导入和导出。导入兼容 MoviePilot 的顶层 JSON 数组，逐项报告新增、更新、跳过或失败；同站更新保持稳定 ID，保留其他站点。设置页不重复提供资源站点表单。

qBittorrent 和 Transmission 均允许多个实例，在“设置 → 系统”中新增、编辑、启用、设置默认、排序、删除及分区保存。界面不要求下载器路径映射或默认下载目录，路径由容器 bind mount 提供。停用实例不能参与新下载选择或后台监控。

下载确认选择下载器和实际保存目录，可使用默认/自动值；不要求先选媒体库、影视身份或季集范围。订阅同样配置下载器与下载目录。媒体库目的位置由全局目录规则决定。

“下载管理”沿用原版按下载器页签展示下载卡片，只显示本应用认领或带 light-media 标签的下载中任务。qBittorrent 使用 downloading，Transmission 使用下载等待/下载中状态。开始、暂停、删除须作用于核对后的目标任务，不接管原 MoviePilot 或下载器中的全部任务；不显示独立做种任务，也不在下载卡片增加手动整理入口。

## 订阅与日历

电视剧以季为单位订阅，可选择开始集数、总集数、关键词、站点、资源条件、下载器和保存目录。多季保留各季独立范围；不要求逐集创建订阅。编辑使用原版 720px 弹窗、基础/进阶页签、字段顺序、outlined 控件及固定底栏，季号放在进阶。

保留用户确认的自定义更新星期/时间、检查频率、例外日期及人工集号映射。更新时间与检查频率分别管理：预计周五更新，不代表此前完全不检查；更新窗口内加密检查，窗口外保留低频缺集核对。预测不能伪造已确认播出集号，TMDB 刷新不能覆盖人工映射。

日历提供月、周和日程列表，点击事件可查看详情并进入对应订阅。取消订阅不等于删除已下载文件或下载器中的种子。

## 目录与文件管理

目录规则只管理源目录、整理目标目录和相关整理选项，可折叠、排序并整体保存；不关联下载器，也不要求关联飞牛影视库 GUID。下载完成后，由所选目录的监控/下载器监控触发整理；无匹配规则或不整理时保留下载位置。

只处理本地/NAS 目录，不增加云盘、网盘上传或云存储页面。不提供独立媒体库内容、库存扫描或原位登记入口；内部资产索引继续服务于去重、订阅、整理及对账。

文件管理采用原版存储面包屑、可切换目录树、通配符与大小写过滤、目录/文件单击行为、桌面行操作、移动端菜单和显式多选模式。多选时整行可切换选择，勾选框有完整点击区域；同目录刷新/排序保留有效选择，换目录清空。文件列表应使用剩余页面高度。

创建、重命名、删除只进行一次面向用户的确认；身份、授权范围、文件快照及冲突检查由后端完成，不增加额外必选步骤。

## 手动整理与整理历史

文件管理和整理历史共用“手动整理”弹窗。目的存储、方式、目的路径和类型默认自动，TMDB 编号可空；选择类型后可查询或输入编号。电视剧支持季、集范围、集数定位、偏移，另保留 Part、最小文件大小、按类型分类及刮削选项。

目的路径允许直接输入、清空和目录树选择，目录展开不等于选中。目的存储、整理方式、目的路径及分类/刮削开关相互独立，修改一项不能重置其他项。全局默认硬链接，无需设置一个额外的全局整理模式；目录规则和手动操作中的显式选择继续生效。

“按类型分类”使用原版有序二级分类策略，例如华语电影、外语电影、动画电影及国漫，不能仅创建电影/电视剧目录。人工选择优先于目录默认值。

“预览”是可选操作，展示在弹窗内容底部，始终显示“预览”；每次点击按当前表单重新请求，请求中避免重复提交。操作栏固定底部，支持“加入整理队列”和“立即整理”。立即整理显示进度，成功后关闭并刷新，失败保留表单与明确原因。

整理历史支持搜索、状态筛选、排序、分页、分组、单条/批量重整及队列取消。相同源资源重复整理更新同一条可见记录，保留稳定 ID；内部各次计划和恢复收据继续保存。预览不生成执行历史。

删除确认保留四个明确操作：仅记录、记录加源文件、记录加媒体库文件、记录加两端文件。批量选择后有可见入口，逐项核对当前执行身份、文件归属、快照和做种使用；失败项保留选择并显示原因。

## 元数据与飞牛影视

TMDB 支持 API key 或读取令牌，供影视身份、详情、演员、季集及推荐查询。凭据可从用户授权的原项目配置或密码库中复用，经内存传递并加密保存，不进入 Git、普通日志或命令行参数。

识别、整理、NFO/图片刮削和入库核对使用真实作品及单集身份；标准来源 ID 不由飞牛内部 ID 推断。识别不确定时提供人工修正入口，不猜测后改写文件。

飞牛影视允许直接填写 http://私网IP:5666 或 https://私网IP:5667，自动补齐 /v，兼容同主机 HTTPS 升级及该本地 NAS 的自签证书。无需改用 8005、手动填写库 GUID或把绝对路径绑定某个影视库。凭据不能跨主机转发，不能向 HTTPS 降级目标转发。

## 日志与后台任务

日志是必要功能，提供实时跟随、历史查询、级别/关键词及模块/站点/流程/任务筛选、局部 DEBUG 和当前筛选导出。后台任务展示具体动作、作品/文件、当前阶段、源/目标和最近错误；内部编号收在详情中，不能只展示不明任务 ID。

失败状态、通知和恢复操作必须关联实际执行。网络超时、未知下载器提交结果、文件系统变化及进程中断不能变成成功或无条件重放。已开始的交接按已确认阶段核对和收尾。

右上角移除全局暂停按钮，个人图标使用登出图标；不提供数据库备份界面/公共 API。插件日志内部的暂停日志流、跟尾控制仍保留。右侧不重复显示菜单标题、英文眉题或用途说明，保留实际操作控件、分区标题和必要字段提示。

## 插件平台与全部已安装插件

插件平台按原版完整操作迁移，包括我的插件/市场、仓库来源、安装/版本/重载/卸载/重置/分身、动态配置、数据页、动作、日志、仪表板、文件夹/混排、快捷访问、服务/命令/事件/工作流与实际依赖的模块/认证能力。逐项契约和输入输出见[45项平台验收表](plugin-original-platform-audit.md)。原版卡片的运行圆点来自插件自身状态，不增加统一启停开关代替各插件配置。

原实际安装清单为 23 个实例，包含 TorrentTransfermusic 分身。配置、KV、独立文件、启用状态、分身关系、站点/下载器/目录/媒体服务引用及用户布局均需迁移；版本与完整名单见[迁移清单](plugin-installed-migration-baseline.md)。Go 运行器不直接执行原 Python 包，每个实例需要真实的 Go 业务实现。

迁移不能自动重放 onlyonce 等一次性动作，不能让旧系统和新系统同时执行同一组定时写操作。未就绪依赖和未映射引用必须可见；配置复制、空卡片、固定成功及 HTTP 200 均不能作为插件完成依据。

辅种、转移做种、自动签到、刷流和清理等已安装插件纳入上述逐项迁移。持续做种仍由下载器承担；有明确结果的辅种/转移操作由插件执行，不新建永久“做种任务”模块。清理功能必须分别处理原文件、媒体文件、整理记录和种子，保留原插件不同的停止与延期语义。

## 技术实现与交付验收

Go 服务嵌入 Vue 静态页面，SQLite 保存业务状态，敏感配置和插件状态使用加密存储。插件使用按需 Go 子进程与版本化 stdio 协议，持久计划和副作用由可信宿主管理。连续文件监听可保留长期 Go owner，不允许每次短工作器退出都提前执行或丢弃其队列。详细接口、持久化、生命周期及当前差异见[插件技术方案](plugin-runtime-architecture.md)。

主程序保持独立目录、数据库、镜像和端口，不修改旧 MoviePilot 或旧 Go 项目。实机验证使用独占测试目录/容器和合成文件；既有媒体与种子不作为破坏性测试材料。

每项交付需具备可操作前端、真实后端、状态与失败处理、对应原版行为、配置/数据/文件迁移收据和适当的联调证据。普通测试、竞态、纯 Go SQLite、浏览器交互、协议参考和 NAS 实机证据分别记录。资源验收覆盖整个进程树的 RSS、CPU、I/O、缓存与并发；低内存隔离用例通过不能替代完整应用的 72 小时混合负载验证。

初始设计的详细模型与历史取舍保留于 [design v1.4](design-v1.4.txt)；与当前要求冲突时，以本文、[AGENTS.md](../AGENTS.md)及用户最新明确要求为准。实现进度与部署状态分别记录，不能把开发分支测试通过称为用户已经可用。
