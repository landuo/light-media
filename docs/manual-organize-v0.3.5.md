# v0.3.5：独立编辑整理目标与批量删除

按用户 2026-10-15 的反馈修正手动整理和整理历史，已发布到独立 light-media 容器。

## 变化

- 目的路径可手动修改、清空，保留现有目录建议；空值使用「自动」占位提示，不再向输入框回填文字。
- 移除目的路径变化时重写目的存储、整理方式、刮削和分类开关的 watcher。三个目标字段彼此独立，修改只使旧预览失效。
- 显式开启「按类型分类」后保留该选择，并实际整理到目标下的「电影」或「电视剧」子目录。原版的类型分类与类别分类是不同选项；本次未增加类别规则。
- 整理历史勾选后显示「批量删除（数量）」。保留一次确认的四种范围，明确列出「删除媒体库文件和整理记录」「删除媒体库文件、整理记录和原文件」。
- 每条删除继续携带稳定历史 ID 和当前 file_id。只有服务明确返回 deleted=true 才计成功；失败项继续选中，成功/失败数量与原因不会被定时刷新清除。

根因是原前端在编辑目的路径时，用目录默认值重置分类开关。后端的分类路径生成与显式布尔值优先级正确，本次没有修改该业务逻辑，也没有更改删除权限或做种源保护。

## 验证

- 全量 Go 测试、纯 Go SQLite 测试、go vet 通过。新增手动分类 HTTP 回归的普通、modernc 与 race 测试通过。
- 前端类型检查、59 项测试、生产构建通过。组件回归直接执行真实 SFC 的事件与 watcher，验证路径清空、字段独立及分类 true/false 的提交。
- 电影/电视剧、分类开关四组合经认证 HTTP 入口执行真实本地整理，并从历史切换开关再次整理。显式路径与方式优先、源文件保留、旧受管目标清理、历史仍为一条。
- 本地浏览器实测修改及清空目标、切换存储/方式后分类仍选中；预览显示目的目录下的「电影」子目录。
- 四个独占合成文件经页面分两批删除：第一批两条仅移除媒体库文件与记录，原文件仍在；第二批两条移除两端文件与记录。核对文件存在性及历史查询 total=0。
- 本地模拟下载器不可用时，两条删除均停止且保持选中，页面保留具体原因；恢复本地空任务协议模拟器后重试成功。该验证未连接或操作真实下载任务。
