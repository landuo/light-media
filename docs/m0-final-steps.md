# M0 剩余验收步骤

当前 M0 仍是部分验收：10 项交付物中 6 项通过、4 项部分通过，6 项进入 M1 条件中 4 项通过、2 项部分通过。这里保留原始验收范围，不把新离线工具、编译或合成测试当成真实三代表样本完成。

## 已准备的来源到 NFO 工具

`cmd/metadatacheck` 固定核对夜王电影、生活大爆炸父剧及 S07E17、诛仙父剧及 S04E05。它只从 stdin 获取授权的自用凭据，未配置时零请求并返回未验证。具体 API、身份与错误契约见 [metadata-contract.md](metadata-contract.md)。

新 `experiments/metadata-nfo` 不请求网络，只核对该五条报告并生成对应五份 XML 的计划。要求全部记录通过、来源为 TMDB、每个 sample 唯一、类型/固定 ID/父剧上下文/季集/日期一致。单集 uniqueid 使用单集自己返回的 ID，父剧 ID 只用于父关系。相同数值在不同类型命名空间中不被合并。该工具保留输入和五份 NFO 的 SHA-256；报告声明、哈希和 run ID 均不能独立证明远程来源真实性。

工具默认不写文件，只有明确的新 work 直属目录和 apply 才创建五份 NFO。验证与全部 XML 编码在创建目录前完成，失败输入不落盘；不覆盖既有根目录或文件。根电影/父剧只写所确认的标题、年份和 ID，完整来源日期保留在清单；单集额外写 showtitle、season、episode 和 aired。它不生成图片、视频或演员，不创建飞牛媒体库，也不改既有合成实验工具。

## 还需真实证据的步骤

1. **取得授权的标准元数据输入。** 使用用户自用 TMDB 凭据或能提供同等明确命名空间/单集上下文的合法来源。保留实际请求产生的安全报告和执行日志；不能使用旧应用的内置公用 Key，不能把 Trim 前缀当标准 ID，不能把合成结果改标为真实结果。
2. **准备并核对 NFO。** 对真实五记录运行离线工具，在独占目录生成五份 XML，再解析核对来源 ID、作品类型、单集自身 ID、父剧/季集和日期及文件哈希。局部 XML 编码通过只证明这一步，不证明飞牛读取成功。
3. **先确认真实标准 ID 导入的作用域。** 当前只读 schema 研究未取得 DDL，公开客户端也没有提供已证明的独立状态或 local-only 接口。必须取得独立测试服务状态或可复核的共享作用域证据；UUID 媒体库/目录/GUID 不能代替 provider、演员、图片缓存隔离。参见 [fnos-identity-isolation.md](fnos-identity-isolation.md)。
4. **受控导入与实际读回。** 使用新的合成小视频作为载体，不复用做种文件。只操作测试实例或已证明作用域内自己的库；读取真实路径关联、ancestor/parent、作品类型/标题/年份、正确季集/日期，并独立报告标准来源 ID 是否直接返回。仅父剧＋正确季集的关系定位不能冒充独立单集 provider ID 读回。
5. **清理并关闭验收项。** 根据精确清单清理自身测试库/文件，并记录服务版本、原始结果、比较及边界。逐项关闭 D03、D05–D07、G03、G04，全部满足后才标记 M0 完成。没有实际证据的字段继续列为未验证，不以测试通过替代实机验收。

目前真实元数据凭据不可用，标准单集身份未取得，步骤 1/3 尚未满足。新工具使后续验证可以复现，不改变该状态。M1 UI、生产下载/整理闭环、72 小时完整应用负载和 P1 插件运行器不被提前加入本次 M0。
