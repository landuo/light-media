# M0 integration probe contract

This is a read-only protocol validation CLI, not a production downloader manager or a completed five-site adapter. Implementation and fixtures are standard-library Go. Automated tests use **synthetic localhost httptest**. A separate authorized live M0 run has now read the NAS downloaders and five sites; observed scope and versions are recorded in docs/m0-report.md and docs/m0-evidence.json. Automated fixtures remain synthetic, not captured private pages.

## Input and invocation

Build: `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o work/integrationcheck-linux-amd64 ./cmd/integrationcheck`.

Run `./work/integrationcheck-linux-amd64` on Linux with one JSON object on **stdin**, supplied by an authorized in-memory credential provider. Do not put real input in a shell argument, environment variable, ordinary input file, Git fixture, or report. The JSON schema is:

```json
{"downloaders":[{"id":"stable-instance-id","kind":"qbittorrent","base_url":"https://example.invalid/proxy","username":"","password":""}],"sites":[{"id":"stable-site-id","kind":"mteam","base_url":"https://example.invalid","cookie":"","api_key":"","query":""}]}
```

IDs must be stable opaque labels, ASCII letters/digits/`_.-`, at most 64 characters; never use a secret as an ID. Downloader IDs must be unique. Supported downloader kinds: `qbittorrent`, `transmission`. Site kinds: `mteam`, `hhanclub`, `ubits`, `jiayuan`, `1ptba`. A kind is a caller assertion, **not automatic domain identification**. No known/private domain is embedded or guessed. In particular `jiayuan` does not imply HDHome or PTHome.

qB base URL is the WebUI/proxy prefix; `/api/v2/...` is appended. Transmission base URL is the exact RPC endpoint, preserving a supplied proxy path; a bare origin uses `/transmission/rpc`. MTeam base URL is the explicitly supplied API origin/prefix, not a front-end address from which we invent an `api.` hostname; `/api/member/profile` and `/api/torrent/search` are appended. Other sites receive the explicitly supplied base with `index.php`, then optionally `torrents.php`.

Input cap: 64 KiB, at most 10 configured instances/sites, query at most 256 bytes. Each request has a 10-second timeout, decoded response body cap 1 MiB, maximum 10 requests per target; CLI has a two-minute overall context. No automatic rate-limit retry. **All redirects are rejected**, including same-origin redirects: this conservatively prevents cookies/API keys/basic credentials or login POST bodies reaching another origin or downgraded protocol. Supply the final authorized endpoint; never disable TLS validation. URL userinfo, query parameters, and fragments are rejected. Standard TLS validation remains enabled.

## Read operations and output

- qB: cookie login (`Ok.` plus SID cookie required), version and WebAPI version, preferences (only path-field presence summarized), torrent info with `limit=1`, one hash-scoped file list. No add/pause/resume/recheck or torrent material export. The full preferences response is bounded, transient, and never emitted.
- Transmission: legacy `session-get` bootstrap and bounded 409 session-id handshake; RPC version 18+ selects JSON-RPC 2.0 `session_get`/`torrent_get` and snake_case fields. Legacy RPC 17 uses the prior envelope/field names. A read-only `recently-active` / `recently_active` list selects at most one torrent for `files`. The modern protocol first requests only hash and file_count metadata, selecting the smallest eligible positive count up to 1000; no eligible sample stays unverified. This avoids fetching a huge first torrent. The legacy path retains hash-only sampling and can hit the body cap. Transmission has no list limit here; all responses retain the 1 MiB cap. An empty recent list means **file validation not performed**, not an empty downloader. Numeric torrent ID is never used as durable identity. Future servers that remove legacy bootstrap fail visibly until a new negotiated bootstrap is implemented.
- Identity in memory: `TaskIdentity{InstanceID, Hash}`, normalized hash case. Summary emits only SHA-256(instance + separator + hash) truncated to 128 bits. Raw hashes, file names, paths, titles, full URLs, response bodies, cookies, tokens, and passwords are not emitted. Version output is constrained to a version-like grammar; server error text is never echoed.
- Capabilities separate `protocol_known`, `read_observed`, and `write_verified`. All write verification remains false; this CLI implements no writes. Protocol-known means the documented operation exists, not permission/version compatibility or test success. qB `relocate_existing` is intentionally not claimed: moving data is not a proven no-move reassociation API. Read samples do not validate ownership, labels, selective download completion, relocation, metainfo availability, or cross-client migration.

Output is a JSON `Report` with per-target stage/status, request count, version/protocol where recognized, sample/file counts, path-field count and capabilities. `evidence: live_request` means the adapter performed an HTTP probe, **not certification of the target as production**; fixtures use localhost servers and must be labeled synthetic in test reports. Exit code 0 means requested read probes completed (`ok` / `empty_result`); 1 means incomplete/unverified/failed; 2 means invalid JSON or input size. No input means no network and `unverified`. No successful HTTP status alone establishes business success.

Statuses include `authentication_failed`, `forbidden`, `login_challenge`, `rate_limited`, `redirect_blocked`, `business_error`, `protocol_changed`, `body_limit`, `request_limit`, `transport_error`, `invalid_input`, `unsupported_kind`, and `unverified`. Authentication/business errors and template changes never become empty search results.

## Five-site validation boundary

MTeam: sends only `x-api-key`, POSTs profile check, requires business code zero and a nonempty positive numeric scalar profile ID; optional search sends one page of ten results. Does not log into `/login`, use cookie fallback, create a token, call administrative APIs, or fetch private torrent download materials. Unknown business codes return `business_error`; HTTP/known auth failures are distinguished. Profile/search schema began as a candidate based on fixed MoviePilot source; the separate authorized live M0 run has now validated authentication and one limited search page on the configured target. This does not establish a completed release parser or production adapter. Protected materials have a separate probe and evidence contract.

The UBits, Jiayuan and 1PTBA kinds currently use a **shared conservative NexusPHP candidate probe**, not complete independent site-specific parsers. Check requires logout and user-details links, and rejects recognizable login/challenge pages. Optional search fetches exactly page 0; requires an authenticated-looking page and a torrents table, counts distinct detail IDs only inside the balanced recognized results table, and only calls it empty when an explicit recognized empty message is present. HTML is inspected with narrow regular expressions; it does not claim robust DOM/resource parsing. Variants, JS-rendered tables, unusual login markup or custom site layouts return `protocol_changed`. Generic synthetic success does **not** establish support for any real site/domain. A separate authorized live M0 run has now checked each configured site's authentication and one bounded search-page shape; those observations are recorded in `docs/m0-report.md` and `docs/m0-evidence.json`. Fixtures remain synthetic, not captured private pages. Full release attributes, freeleech expiry, pagination beyond page one and recent feeds remain unimplemented/unverified here. Resolve and protected .torrent material handling use a separate probe/evidence contract rather than this read-only integration CLI.

HHanClub has an explicit M0 exception based on the authorized, sanitized live tag/class summary in `work/hhan-page-shape.json`: the observed search input is `id=searchinput/name=keyword`; the grid is `div.torrents-table`, with `div.torrent-table-sub-info` rows containing `div.torrent-table-for-spider-info` and `details.php?id=` links. Its probe sends `keyword` plus page 0 and requires those exact class tokens in balanced div fragments. An empty grid alone is a template failure; empty requires an explicit recognized message inside the grid and no malformed result rows. Other HTML kinds retain their original table requirement. New fixtures are **synthetic**, reconstructed from the shape summary, not captured private pages. This selector update does not validate resource attributes, protected download URLs, pagination or production compatibility; the subsequent authorized live recheck succeeded for one query/page; full resource attributes and material retrieval have separate gates.

## Protocol evidence reviewed 2026-10-14

- [qBittorrent official WebUI API 5.0](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-%28qBittorrent-5.0%29): cookie login, app/version, app/webapiVersion, app/preferences, torrents/info and torrents/files.
- [Transmission current official RPC specification](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md): 4.1 introduces JSON-RPC 2.0 and snake_case; RPC 18; 409 header handshake; stable hash identity. [4.0.6 specification](https://github.com/transmission/transmission/blob/4.0.6/docs/rpc-spec.md) supplies the legacy envelope and names.
- [MTeam official API policy](https://wiki.m-team.cc/api): third-party API Access Token via x-api-key; member/profile is allowed; policy distinguishes forbidden login/admin/key-management routes. Full Swagger requires account access; this implementation did not access it.
- Fixed read-only reference: MoviePilot `1528176beacc0f9f8d8d9cbf1adf048b0da67b5c`, `app/chain/site.py` MTeam profile/1PTBA index check, `app/modules/indexer/spider/mtorrent.py` search shape. No old project files were changed.
