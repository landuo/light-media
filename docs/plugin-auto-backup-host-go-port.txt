AutoBackup 2.1.4：实际主程序接线

本批在 Go 宿主接入自动备份的原表单、配置、once/cron、API、SDK 和实例生命周期。
此前的纯包来源与199条原执行参考，继续保留在 plugin-auto-backup-go-port.txt；
纯包12个生产Go文件与2份embed未改变。本批不引入Python或其他运行依赖。

原操作和实际存储

安装目录增加AutoBackup。配置保持原版字段与falsey/warm/cold语义，onlyonce
在同一事务保存关闭标记与3秒后的持久date计划，重启不重新定时。cron使用
实际宿主时区，不硬编码上海；既有历史通知不随后来时区改变而改写。

真实App使用light-media.db，备份由Store的一致SQLite快照生成，包含恢复密钥
secret.key及category.yaml。没有顺序复制仍在变化的DB/WAL，也没有因为找不
到原版user.db就返回空ZIP成功。归档及恢复密钥0600，临时目录0700。备份默认
输出到本实例私有目录，配置其他路径必须通过现有宿主可信授权根。

快照包含原备份自己的进行中任务。在任何ZIP/保留清理/WebDAV发生之前，只在
自有VACUUM副本写入认证snapshot_cut：保留原run/input/once/owner/deferred证据，
取消该快照自己的旧动作。实际数据库及其他未知执行原样保留。独立App从ZIP
恢复后可解密并读回合成数据，旧动作不回放；不同DataDir需显式修改旧绝对路径，
不能自动写入原实例目录。

本地保留清理使用原ctime排序，冻结dev/inode/mode/size/mtime，并对每一步保存
意图和确认。嵌套文件在同inode改写会阻止删除；未知结果停在待核对，不盲重试。
WebDAV使用受控HTTP客户端和TLS校验，分别记录上传和删除的意图/确认。实例
gate只阻塞自身长IO，不把全局配置锁持有到归档或远端传输完成。

单实例配置/reload/reset/uninstall和批量PluginUnInstall使用同一owner收尾入口。
SDK调用受run/config/generation和opaque request ID约束，原HTTP输入仍保留在
认证admission中；不是从配置值随意给worker文件系统或数据库权限。

独立恢复证据

每个安装代际在安装/reset/uninstall/批量卸载事务中创建独立认证根，绑定本代
执行记录摘要、序号和前代摘要；读取与普通运行不能重新初始化根或记录。
执行记录、根和真实run/deferred事实交叉校验；单行或整份私有记录缺失、
不一致不会被误当首次运行。缺证据保留待核对诊断，不提供放弃或重建入口。
数据库查询、上下文取消等错误保持原错误，不伪装成缺证据。启动仅隔离已知
证据缺失/记录损坏/待核对状态，固定日志说明原因；其他SQL错误返回调用者。
这不证明整个数据库及其全部根一起回滚时存在外部新鲜度保证。

旧任务未知时，新备份在任何效果开始前被阻止，并保存严格的零效果失败
收据。多次重试不会额外产生需放弃的未知执行；原未知effect与输入原样保留。
只需核对并放弃原未知任务，随后才可发起新的明确备份。

通知与恢复

源通知接到既有认证历史、私有事件和共享路由队列，使用带持久时区的v2源封套。
接受通知或排入渠道队列不等于实际外部投递成功。实际账号通知未发送。

执行记录显示固定阶段名和待核对说明；认证同源管理请求须显式确认后才能
放弃未知执行。放弃保留完整原effect与deferred证据，取消旧run/occurrence，只
开放新的明确动作；不回滚文件、不重试旧动作。证据损坏时不提供伪造修复。
浏览器已经实际打开合成未知ZIP写入任务，确认后显示已取消，按钮消失、证据
保留提示可见。截图与操作记录见plugin-auto-backup-host-verification.json。

范围与限制

本App目前只有SQLite后端，不把纯包pg_dump适配和本机真实PG样本称为实际
App支持PostgreSQL；此前NAS缺initdb的那一项仍为SKIP，未改写成通过。
owner journal上限16MiB，暂不自动裁剪历史；达到上限会显式拒绝而非丢弃恢复
证据。
本批不恢复全局数据库备份菜单。原MoviePilot的AutoBackup七个历史文件仍未
正式读取迁入，原23个实例配置/KV/文件正式迁移数量仍为0，没有部署或启用
用户实例。代码目录增加一个可执行处理器，不等于23个插件已经迁移。
