# M0 逐项验收矩阵

审阅日期：2026-10-15。依据 `docs/design-v1.4.txt` 第 13 节，**M0 交付物 10/10、进入 M1 条件 6/6 在下列有限范围内通过**。实机操作与原始摘要由主任务执行和保存；本次文档更新只读核对证据，没有追加接口或 NAS 操作。初次审阅基线 `14cb72f` 后补齐的代码、实测和失败记录分别列明，不将历史运行合并成一次成功。

这一结论允许开始 M1，不表示完整应用、所有飞牛字段或下载/整理端到端已经验收。**飞牛标准来源 ID 的直接读回仍为 `unverified`**；不能因此宣称后端没有保存 ID 或不支持某种 NFO 标签。

## 原始要求与判定口径

原始 M0 交付物：

> 五站协议样本；两类下载器版本/能力检测；飞牛兼容验证；真实 NAS 路径/硬链接验证；一部电影、一部普通剧及一部常看国漫的命名/NFO 样本；Go+SQLite 内存基线；日志与扩展接口草案。

进入 M1 的原始条件：

> 五站和双下载器接入可行；飞牛读取样本 NFO；实际挂载与稳定身份成立；确定驱动及基线，接口错误可追踪。

“通过”仅覆盖列明版本、接口、目录和样本。合成回放不代替实机，HTTP 200 不代替业务或字段检查，空字段不记为读回成功。独立服务实例、获取飞牛数据库 DDL、证明全局缓存完全隔离均不是原始 M0 的额外前置条件；相应未知事实仍披露。库配置及三个既有条目的有限快照不变，也不能替代全库或共享状态审计。

## 两轮标准来源 NFO 实机证据

官方固定 HTTPS 探针 `work/live-metadata-authorized-source.json` 为 `live_request`、5 GET 全部 `ok`；两集父上下文是 `verified_series_and_fixed_request_route`，不冒充响应中存在 show_id。离线生成/比较器只验证提供的报告及文件，自己不认证远端来源，故其 `input_source_authenticity=not_independently_verified` 保留原义。

| 运行 | 实际结果 | 清理与边界 |
| --- | --- | --- |
| v1 `24dd83d2-28d9-4052-8ebd-0282d808cf2f` | 官方五条标准记录生成五份 NFO；observe 7 节点；inspect 32请求/66事件，通过已证 `GET /media/itemfile/:guid` 实际返回 3 条 owned canonical 路径。`work/nfo-real-compare.json` 为 `passed`，30 项检查通过。 | 三个既有条目的有限 before/after 快照相同，各 17 请求；不是全库比较。cleanup 6 请求确认库不存在、原有七库配置不变；8 个自建文件经清单/哈希核对删除，目录消失。 |
| v2 `63a741d5-3dfb-4319-b512-ebd324d81128` | 在同类五份 XML 加入标准 `tmdbid` 兼容标签并保留 uniqueid；observe 7 节点、inspect 32/66、3 条实际路径；`work/nfo-real-tmdbid-compare.json` 同样 `passed`、30 项检查通过。 | before/after 各17请求、3条既有详情及库配置相同；cleanup 6请求、原有七库不变；8文件核验删除。此轮 API 仍没有可证明的标准 ID 直接读回，不能认定内部未保存或不支持标签。 |

两轮均 `direct_standard_id_readback=unverified`。“没有冲突的显式 ID”只表示未观察到相反的标准 ID，不是“标准 ID 已读回”。三种样本的来源身份、XML、自建文件、实际条目父链和字段/路径关联各自有证据，不能混写为 API 返回了 TMDB ID。

证据文件为 `work/nfo-real-*.json`、`work/nfo-real-tmdbid-*.json` 及对应 `.jsonl`（具体文件名见 `nfo-verification-plan.md`）。`work/real-experiments-final-cleanup.json` 确认两库和 16 文件清理、自建根不存在、凭据 broker 已退出、自有 NAS staging 已移除；`global_cache_reclamation` 仍未验证。没有使用真实视频或改写既有媒体。

## 留给 M1 及后续阶段的事项

- 发布使用已实测 canonical 目录；核对类型/父链/季集/字段及实际文件，不匹配进入待确认，不自动更改目标来迎合错误结果。
- 应用保留来源命名空间和自己的资产映射。飞牛标准 ID 暴露方式仍未知；不能将空 trim_id 解释为内部未存储，或将不透明来源 ID 猜成 TMDB ID。
- movie/tvshow 年份与 sourceDate 分开；TV根演员为空、Season/Episode演员和顺序规范化、首次同字节图片及 namespaced E01 失败均保留兼容说明。
- 三个既有条目有限快照/库配置相同不证明全局缓存、演员表、所有条目或图片共享状态无变化。`fnos-identity-isolation.md` 的只读研究没有取得 DDL，此未知不作为新增 M0 阻断。
- 完整筛选/下载/整理端到端、日志中心/持久任务、全局暂停、72小时资源验收、全部双下载器写操作及 P1 插件，按原设计后续阶段验收。

主任务最终 `make check` 和 `make build linux-amd64 experiments` 均退出0。它们证明当前代码检查和构建通过，不替代上述实机证据，也不把剩余应用功能计为已交付。
