完整实际 loopback 还覆盖：SDK Runner→Serve→opaque ID→Go核心→受控HTTP；multipart文件/语音及附文；无预先card/message grant的 CardKit完整终态；PUT断连不得普通edit fallback；confirmed重放不得重复网络；unknown/收据提交失败阻断第二消息；联系人与资源授予、显示文件名只用冻结bytes；token后复核Guard；redirect不跨origin带凭据；私密API错误不入公开结果/KV。HTTP比较方法/地址/头字段/JSON树/MIME/字节及故障前缀，不声称 requests 与 Go 任意原始JSON或multipart boundary逐字相同。

可接入 API 与缺失宿主

New(PluginHost)、Init(Object)→epoch、Stop/State/Modules、SyncAdmins；ParseMessageBody/Post/PostMedias/PostTorrents/Edit/SendDirect/Finalize/ProcessingStarted/ProcessingFinished/DownloadImage/DownloadFile/AddReaction/DeleteReaction；Form/Page/Test/Status/FetchChats；DecodeSourceWebhook/DispatchTrusted；NewAdapter(Binding,Journal,Options)。完整字段与逐项顺序见冻结 MIGRATION.md 与 source-contract.json。

仍未接入：持久 owner/冻结 invocation envelope、加密SQL Journal/两KV、配置与Notifications提交时CAS、13方法真实dispatcher/通知生产者、真实MessageChain与用户绑定查询、真实MediaInfo/Context消费快照、可信ingress认证/防重、配置UI、旧配置与数据迁移。接口存在不能当作宿主已经完成。Init没有脱离owner的后台线程，必须由宿主按epoch调SyncAdmins；MemoryJournal仅测试，跨进程/新invocation的unknown必须由durable owner阻断。

原 source challenge先于认证返回，encrypted/card.action.trigger跳签。DecodeSourceWebhook.Accepted只表示原检查事实，不能给anonymous事件发信/命令/资源能力。生产需另建可信事件grant。接收者、contacts、文件bytes及资源pair由宿主冻结，worker仅交不透明ID。成功持久收据才派生新message/card/image/file/reaction；管理员查询不自动授权为接收者。

固定 HTTPS Lark地址、受信CA验证、禁止带凭据跨origin redirect不变；飞牛局部自签例外不扩至此。远程图片只接宿主授权URL的预取bytes/Content-Type。原 remote-image suffix和实际fresh152项strict MIME registry已对照，但不复制其他旧运行模块可能动态add_type的进程全局。

仍保留的输入/安全差异

孤立UTF16 surrogate、完整NaN/Infinity及指数溢出JSON语义、任意Python对象/循环repr、所有非表单配置动态类型和未消费Pydantic模型不是已实现范围；检测到已知不支持表达返回明确非成功。CardKit裸非有限JSON不落入空2xx成功，已有请求收据为unknown。无序Go map不能猜插入顺序。媒体view明确只是消费属性，不冒充完整MediaInfo识别。

源图片辅助在None后仍记sent，Go仅记录confirmed成功。源API错误可回显秘密；Go仅保留已知contact权限事实，其他采用固定脱敏文字。错误吞掉的分支向可信宿主保留失败/unknown，不伪装已送达。原随机remote临时basename在Go以固定owned名称表示。资源URL段拒绝路径注入，只接受正常Lark ASCII ID。这些差异不得描述为原版逐字相同。

原 form 的AppSecret动态显隐literal继续完整保留，正式UI的窄可信密码显隐由另一批独立验证；不把它计入本叶包测试，不执行任意JS。
