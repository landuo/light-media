实际执行顺序

源 Notice 调用先校验 Notification，并在一个事务中保存完整密文、原始
effect/Core 收据、站内历史及路由初始摘要。实际 Journal.Commit 返回后，
同一源调用等待 AfterNotice 完成；此时尚未执行其后面的配置修改。
Router 的 history/switch/user/publish/queue 回调分别记录输入、结果与前序
摘要。已提交前缀不会因为后续错误被删除；配置不能越过失败的通知调用。
每次恢复核对完整源收据、密文信封、历史摘要与连续阶段，遗漏或篡改拒绝。

允许时段或 immediately 分支在源调用返回前等待发送尝试。窗口外仅接受
持久 FIFO。网络调用不持有 SQLite 事务、核心生命周期锁或插件工作器槽。
普通发送器异常沿用原队列的消费语义，单独保存错误；结果未知也单独记录，
不冒充成功送达，不在重启后盲目再发。一个未知消息不会阻止后续 FIFO。
排队消息和源调用等待中的直接消息分别处理，有限扫描不会被旧直接消息
长期挡住。时段在 native init/reload 时读取；改数据库不会暗中重建队列。
通知队列使用 datetime.now 对应的进程本地时间，区别于插件调度的时区。

原通知接受、路由阶段、发送意图和发送结果的提交若丢失返回结果，先读取
精确本地收据。仅当同一参数和结果已提交才继续，不重新保存历史、发事件
或调用发送器；无法证明则保持未知。队列 entry 在调用前深拷贝，发送器
修改嵌套数据不会改写原密文。source run 的历史完成证明另要求新路由完成。

NoticeMessage 与配置隔离

NoticeMessage 在核心发送窗口判断之前提交。公共 domain event 只保存
pnm_ 不透明引用和固定契约；完整24字段、目标映射和消息正文在私有密文。
真实事件收集器核对私有 publication、原源收据及对应阶段，缺事实时不推进
游标，不入队。拥有公开引用不代表拥有发送或调用其他服务的权限。
站内历史仍使用既有清洗投影；缺少用户设置与已有空目标映射保持不同。
switch/user/window/superuser 的宿主存储加密，尚无原配置导入或配置 UI。

App 使用现有数据目录 flock 排除另一个正常 App 进程；单 App 内有路由和
消息的独立 gate，FIFO 有独立 drain。后台恢复只处理已有通知的已接受事实，
不会重放中断的 Clean 函数或为旧配置重新制造下载器/文件/配置写权限。
