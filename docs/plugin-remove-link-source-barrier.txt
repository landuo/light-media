实现
1. 新调用显式带通知位置和同动作序号，使用v3接受事实；旧Effect新增字段均omitempty以保留原序列化身份。旧v1仍本地历史、旧v2仍原异步含义，旧confirmed通知不追补同步屏障。
2. 原授权动作先提交接受事实并对账已确认效果，再暂停写租约、释放SQL/e.mu/生命周期/下载/整理锁；仅按当前精确token交接Router，不能顺带认领另一个实例最旧通知。Host串行动作保持，不能重新进入同Host。
3. Router返回后以原锁序恢复锁，验证同绑定/修订/run/Active/完整durable快照、原根和pins；保留原lease.prior，不重新选择文件。首次通知还冻结文件候选，暂停期间新增或替换对象不能加入删除授权。配置、根、代次或取消使验证不成立时，不恢复写租约。
4. 独立INSERT-only来源结果收据与Router终态同事务写入，绑定实例/代次/效果/位置/序号/接受摘要/初始路由及终态步骤链、异常位置。v3的Complete/SourceError不能仅靠可变路由值证明；确认效果重放、owner启动、deferred retry/outcome都要核对独立结果。
5. 只有受信typed来源异常TypeError、AttributeError、ValueError、RuntimeError才进入原捕获规则；普通SQL/传输错误或相同文本不能经RuntimeError兜底变成已知异常。已知来源诊断不进入致命Machine.Errors；未知结果永久毒化本Machine的后续写入口并保持Active/Blocked，不能因冷启动把通知路由完成就重新授权清理。
6. 丢失SQL ACK只有限读回精确证明，不重发。外部MessageQueue的发送未知/被消费的sender panic不等于原post_message失败；如果Router正常返回仍可得到normal_return。未处理runNoticeRoute回调panic在该窄边界转unknown，恢复锁但不恢复文件租约。本保护不笼统覆盖接受、handoff、证明读取、恢复或其他内部代码panic。
