# light-media

独立的 Go 影视自动化应用，以 `docs/design-v1.4.txt` 的 P0 为需求基线。Vue 页面嵌入 Go 服务；运行时使用 Go + SQLite，无 Python、Node、Redis 或独立数据库依赖。P1 插件、辅种与转移做种仍按后续阶段实施。

## 本次 NAS 使用入口

访问 [内网入口](http://192.168.8.129:3120/) 或 [外网 HTTPS 入口](https://server.accidia.top:28443/light-media/)。管理员登录沿用原 MoviePilot 的账号和密码；新应用使用独立数据库和项目目录 `~/projects/light-media`。新建其他空白实例时，按下方流程首次创建管理员。

下述操作说明对应当前源码。部署版本、构建标识和实机验证以对应交付报告为准；历史备份、恢复、下载与飞牛联调证据见 [P0验收记录](docs/p0-acceptance.md)。完整应用的 72 小时稳定性测试尚未完成。

## 使用应用

```sh
make build
./bin/server --data-dir ./data --listen 127.0.0.1:3120
```

打开 `http://127.0.0.1:3120`，首次创建管理员。构建前端需要 Node；已构建程序启动时无需 Node。Docker 构建及挂载示例见 `Dockerfile` 和 `compose.yaml`，运行用户需具备配置盘与媒体目录的权限。

首次配置入口：

1. 在「站点管理」添加站点并填写 Cookie 或 API Key，可查看账户数据和历史统计。当前提供馒头、憨憨、UBits、家园与 1PTBA 五种原生适配器，支持同类站点的多个实例。
2. 在「设置 → 系统」配置 TMDB、下载器与飞牛影视。下载器从「＋」选择 qBittorrent 或 Transmission，新增停用卡片；点击卡片编辑地址、账号、启用和默认状态，对话框保存草稿后，再点击下载器分区的「保存」。卡片可拖动排序、移除。飞牛配置连接信息，无需手工填写媒体库 GUID 或为绝对路径绑定飞牛库。
3. 在「设置 → 目录」添加全局目录卡片，配置资源目录、自动整理方式与媒体库目录。源目录和目标目录直接填写容器内可访问的绝对路径，也可浏览已有授权目录；目录不关联下载器。可选择目录监控、下载器监控或不整理，并配置硬链接/复制、智能重命名、刮削与按类型分类。编辑及排序后点击目录分区的「保存」。
4. 下载器与应用需能访问选择的同一路径；通过容器启动时的 bind mount 提供所需路径。应用界面不再配置下载器路径映射。硬链接要求源、目标处于可链接的文件系统和挂载布局；需要跨卷复制时明确选择复制或相应回退方式。

页面包括发现榜单、混合影视搜索、演员详情与相关推荐、五站资源搜索和筛选、下载管理、季订阅与日历、文件管理、整理历史、任务、通知和日志。应用不提供媒体库内容页或库存扫描入口。交互以 MoviePilot v2 的已确认 P0 操作为参照，不宣称复制其全部功能或全部高级选项。云盘不包含，P1 插件、辅种与转移做种仍按后续阶段实施。

搜索资源后点击下载，在确认窗口选择下载器和保存目录，再点击「开始下载」。两项均可使用默认/自动；高级选项中的媒体类型与 TMDB ID 用于辅助识别，可不填写。从关键词搜索资源也可直接下载。媒体库目标由目录设置决定，不在下载窗口选择；匹配并启用监控的目录在完成检查后整理文件，无匹配规则或选择不整理时保留在下载位置。五站搜索并发执行，各站完成后逐步显示结果。

「下载管理」按下载器页签展示本应用的下载中任务：任务需带有 `light-media` 标签，或已由本应用持久记录认领；不会接管旧 MoviePilot 或下载器中的其他任务。qBittorrent 使用 `downloading` 过滤，Transmission 仅显示下载等待或下载中的任务；已完成和做种任务不在此页展示。卡片提供开始、暂停和删除，删除会同时删除下载器任务及其数据；此页不提供手动整理按钮，手动整理统一从「文件管理」或「整理历史」进入。

电视剧按季订阅，在「基础」中设置季号、搜索关键词、总集数、开始集数、质量/分辨率/特效、订阅站点以及下载器与保存目录。开始集数包含该集；总集数留空或为 0 时依据元数据，站点不选时使用默认范围。一次选择多个季时，每季单独保存总集数和开始集数。下载器与保存目录可保持默认/自动，在实际下载时解析保存位置。

「进阶」保留资源包含/排除等筛选、自定义更新周期、例外日期、检查频率与集号映射。预计更新时间与资源检查频率分别配置；周期预测不产生已经确认的集号，跟随更新窗口时在窗口外保留低频缺集检查。订阅日历提供月、周与日程列表，星期一开始；点击更新事件查看详情，再进入对应订阅编辑。暂停、取消、内容排除和全局暂停各自保留语义。

「文件管理」使用本地存储面包屑和可切换的目录树导航，默认打开已配置资源目录的公共路径。单击目录进入、单击文件查看详情；桌面端行操作和移动端菜单提供识别、刮削、重命名、整理与删除。进入多选模式后可批量操作；文件过滤支持通配符和大小写切换。浏览挂载目录中的文件不等于提供独立媒体库内容页。

「手动整理」由文件或目录的「整理」操作打开，与整理历史中的重新整理共用同一弹窗。目的存储、整理方式、目的路径和类型默认自动，TheMovieDb 编号留空时自动识别；先选择电影或电视剧后，可输入编号或搜索影视。电视剧可指定季、集范围、集数定位与偏移，另可指定 Part、最小文件大小、按类型分类和刮削元数据。智能重命名等默认行为沿用匹配的目录规则。

「预览」是可选操作，不是执行前的必选步骤；可直接选择「立即整理」查看处理进度，或「加入整理队列」后台执行。服务端在实际执行前仍核对身份、路径、文件快照及冲突。执行成功后关闭弹窗并刷新当前页面，失败时显示具体原因并保留表单。整理使用硬链接或复制时保留源文件。

「整理历史」支持搜索、状态筛选、排序、分页和分组查看；单条或批量重新整理在本页打开共用弹窗，另可查看整理队列及取消尚可取消的文件任务。删除确认提供四种操作：「仅删除转移记录」「删除转移记录和源文件」「删除转移记录和媒体库文件」「删除转移记录、源文件和媒体库文件」。删除文件前仍执行文件归属、快照和做种保护检查，不把记录删除与文件删除混为同一操作。

本轮文件管理、下载管理和整理历史的修正与验证见 [v0.3.1 操作对照](docs/operation-parity-v0.3.1.md)。历史版本的 [v0.2 操作对照](docs/operation-parity-v0.2.md)、[v0.2.2 目录与搜索说明](docs/directory-search-v0.2.2.md) 保留当时的实现和验证边界；其中旧下载器映射、目录关联及强制材料预览流程不作为当前配置方法。HTTPS 子路径 `/light-media/` 的反代约定见 [HTTPS 入口说明](docs/reverse-proxy.md)。

日志中心提供实时跟随、历史游标分页、站点/模块/流程/任务筛选、当前筛选导出，以及可自动到期的局部 DEBUG。后台失败保留通知与任务时间线。诊断导出不包含登录凭据。

「任务队列」直接显示动作、影视季集或文件名、源/目标、当前阶段及最近执行记录；内部编号收在详情的技术信息中。下载提交完成会标为「已提交下载器」，不代表视频已经下载完毕。变更与验证见 [v0.3.2 任务队列说明](docs/task-queue-v0.3.2.md)。

## 配置与恢复

- 服务连接的密码、Cookie 和令牌以 AES-GCM 密文保存在配置数据库。`data/secret.key` 为恢复所需密钥，权限为 `0600`；不要加入 Git 或诊断包。
- 页面创建的数据库备份是 SQLite 一致快照，可下载。另行保管匹配的 `secret.key`；仅有数据库无法恢复凭据。
- 页面恢复前须暂停自动化。服务会校验备份并自动重启，恢复后清除会话并保持暂停；重新登录、核对下载器和文件状态后再恢复自动化。数据库恢复不回滚外部文件与下载器。
- 如需代理，在部署环境设置 `HTTPS_PROXY`/`HTTP_PROXY` 及 `NO_PROXY`；局域网下载器和飞牛应走直连。TMDB 图片由应用缓存供浏览器访问。
- 飞牛同步会验证实际文件路径、媒体库与季集父链。请求扫描成功仅表示已受理，尚未核实的结果保持待核对。
- 原始种子材料仅以AES-GCM密文归档，默认256MiB，配置范围32–2048MiB；未确认孤儿24小时后清理，已关联下载的材料不自动过期。满额会明确拒绝新材料归档，不自动删在用材料。P0只供核心解析，不开放插件/HTTP原材料下载。
- 本次 TMDB 配置按授权取用了原 MoviePilot 项目的共享内置 Key，未在文档中保存其值；长期使用建议在设置中换成自己的 TMDB 凭据，避免依赖共享额度。

既有 M0 探针与协议证据仍保留供开发复现。P0 的实机交付、版本和边界以 `docs/p0-acceptance.md` 为准；72 小时稳定性指标须以实际持续测量为准。

## 开发环境

Go 1.26；本轮使用 Go 1.26.2。默认包含纯 Go SQLite 与 cgo 对照驱动；纯 Go NAS 构建使用 `-tags modernconly`、`CGO_ENABLED=0`。

```sh
go test ./...

```

## 验证程序

| 命令 | 用途 | 实机副作用 |
| --- | --- | --- |
| `go run ./cmd/integrationcheck` | 从 stdin 接收授权配置，探测 qB/Transmission 与五站鉴权、有限搜索 | 登录、只读接口与单页搜索；不加种/暂停/修改设置 |
| `go run ./cmd/metainfocheck` | 五站各最多一页搜索、一份种子材料，验证 bencode 与文件结构 | 登录、搜索及获取材料；仅在内存检查，不保存私有种子、不提交下载器 |
| `go run ./cmd/metadatacheck` | 三作品与两单集的标准 TMDB 身份；stdin 提供授权凭据 | 最多五次固定官方只读 GET；未配置为 unverified，零请求 |
| `go run ./cmd/fnoscheck` | 从 stdin 接收影视账号配置，读取版本、库与少量作品 | 登录与只读查询；不扫描、写入或删除媒体 |
| `go run ./cmd/fnosprovidercheck` | 核对飞牛同源搜索是否返回明确的标准作品/单集身份 | 最多五次版本/登录/查询；不重新刮削，不把 Trim ID 推断为 TMDB ID |
| `go run ./cmd/mediacheck` | 文件名、人工集号映射及 NFO 编码 | 默认离线；显式 `--out-dir` 只在给定工作目录创建新文件 |
| `go run ./cmd/pathcheck` | 明确两个目录后验证硬链接 | 创建并清理自己独占的随机小测试文件 |
| `go run ./cmd/sqlitebench` | SQLite 驱动/事务/异常退出恢复/快照基线 | 新建独立合成数据库，默认清理；不打开业务数据库 |
| `go run ./cmd/nasbench` | Linux 受限容器中测量合成 SQLite 子进程与 cgroup | 固定 `/data` 测试目录；仅适用于隔离实验 |

合成样本可直接复现：

```sh
go run ./cmd/mediacheck < testdata/media/synthetic.json
go run ./cmd/sqlitebench --driver modernc
go run ./cmd/sqlitebench --driver mattn
```

三类真实文件名在 `testdata/media/real-filenames.json`。该输入只验证名称，没有伪造元数据身份；待确认样本使用非零退出码。配置契约见 `docs/integration-contract.md`、`docs/metainfo-contract.md`、`docs/metadata-contract.md`、`docs/media-contract.md`、`docs/logging-extension-contract.md`。

实机凭据由本地密码库/现有授权配置提供，经内存和 stdin 传入。不要将实际输入放入命令行、环境变量、Git、普通配置或报告；`work/` 不纳入版本控制。测试失败时检查结构化原因码，不要关闭 TLS 校验或把接口错误当成空结果。

新 NFO 的隔离实验工具在 `experiments/fnos-nfo`，本地合成样本生成器在 `experiments/nfo-fixtures`，离线字段比较器在 `experiments/nfo-compare`；可用 `make experiments` 构建。前两者默认 dry-run，比较器无网络和写入。飞牛实验只认领新 UUID 库及创建前收据，允许显式操作自己的临时库；它不是生产写入接口，也不证明全局演员/图片缓存隔离。实测结果及未覆盖的字段见 `docs/nfo-verification-plan.md`；`docs/path-baseline.md` 保留 M0 当时的宿主、下载器路径取证和历史建议，当前路径布局以容器实际挂载为准。

HTTP 验证 CLI 的 stdout 为结果 JSON，stderr 为每次运行独立、有总量限制的 JSONL；通过生成的 run、target、request ID 关联。凭据与完整 URL 不进入日志。日志接线验证不能代替业务成功判定。

`experiments/metadata-nfo` 为三代表样本生成标准 NFO：只接受固定五条完整标准元数据核对报告，默认输出计划，显式 apply 才在独占新 work 子目录创建五份 XML。合法 TMDB 身份同时写入同值 `tmdbid` 与 `uniqueid`，单集使用自身 ID。它不联网、不创建视频或演员、不写 NAS；保留 supplied evidence 与输入/NFO 哈希，不把报告中的 `live_request` 声明当成独立的来源真实性证明。未配置报告会在落盘前拒绝。

`experiments/real-nfo-compare` 离线核对五条报告、实际 XML、飞牛七节点和三条服务返回文件路径；固定支持历史 uniqueid-only 与新 tmdbid+uniqueid 编码。真实官方请求及两轮实际关联各 30 项检查均通过。比较器不独立认证来源，也不声称飞牛直接回传标准 ID；真实执行证据与兼容限制见 `docs/m0-final-steps.md`。
